# 26-2 AI 캡스톤: CCTV 영상으로 PM2.5 추정

CCTV 영상에서 이미지를 주기적으로 모아, 나중에 미세먼지(PM2.5) 농도 추정 모델의 학습 데이터로 쓰기 위한 프로젝트 폴더입니다.
현재는 **1단계: CCTV 이미지 수집 MVP** 단계로, 사람이 없어도 며칠간 안정적으로 수집되는지 검증하고 있습니다.

## `APICheck\`: 사전 확인 (완료, 수정하지 않음)

본격적인 수집 전에 "UTIC CCTV 영상을 코드로 가져올 수 있는지"를 확인하려고 만든 폴더입니다. 여기서 확인된 방식을 `Collector`가 그대로 사용합니다.

| 파일 | 설명 |
|---|---|
| `check_cctv.py` | 1회성 확인 프로그램입니다. 목록에서 CCTV 찾기 → 스트림 페이지에서 영상 주소 찾기 → 프레임 1장 저장까지 해보고 결과를 출력합니다. 이 확인으로 영상이 **HLS(.m3u8) 스트림**이고 OpenCV로 캡처할 수 있다는 것을 알아냈습니다. 실행하려면 추가 패키지(`openpyxl`, `python-dotenv`)가 필요합니다. |
| `cctvOpenData_list.html` | UTIC CCTV 목록 페이지를 미리 저장해 둔 파일입니다. 사이트를 다시 호출하지 않으려고 저장본을 씁니다. |
| `OpenDataCCTV.xlsx` | UTIC 공식 CCTV 좌표·속성 파일입니다 (CCTV ID, 센터명, 경도·위도 등). |
| `L020172_20260915_225428.jpg` | 확인 프로그램이 캡처에 성공한 첫 이미지입니다 (용현사거리, 960x540). |

## `Collector\`: 이미지 수집

### `collect_cctv.py`: 수집 스크립트
설정 파일에 적힌 카메라마다 **정각 기준 10분 단위**(00, 10, 20, …분)로 영상에 접속해 프레임 1장을 jpg로 저장합니다.

- **동작 방식:** 매 회차 스트림에 새로 접속 → 프레임 1장 읽기 → 즉시 연결 해제 → 저장
- **시각 기준:** 모든 시각을 PC 설정과 관계없이 한국 시각(KST)으로 처리합니다.
- **실패 처리:** 실패해도 멈추지 않습니다. 한 회차 안에서 10초 간격으로 최대 2회 재시도하고, 그래도 안 되면 기록만 남기고 다음 회차로 넘어갑니다.
  - UTIC IP 차단 기준(동일 URL 1초당 5회 이상 접속 등)에 가까워지지 않도록 접속 횟수를 제한합니다.
- **밀린 회차:** 몰아서 찍지 않고 `skipped`로 기록합니다 (PC 절전 등).
- **연속 실패 경고:** 같은 카메라가 3회차 연속 실패하면 "브라우저에서 스트림 ID 변경 여부 확인 필요" 경고를 1번 남기고, 이후 다시 성공하면 "복구됨"을 1번 남깁니다.

실행 방법:

```bash
# 반복 수집 (종료는 Ctrl+C)
python C:\26_2_AICapstone\Collector\collect_cctv.py

# 1회 테스트: 바로 1장 찍고 종료 (파일명 끝에 _test, CSV에는 result=test)
python C:\26_2_AICapstone\Collector\collect_cctv.py --once
```

### `cameras.toml`: 설정 파일
- **공통 설정:** 캡처 간격, 저장 경로, 타임아웃, 재시도 횟수·간격, 경고 기준
- **카메라 목록:** `[[cameras]]` 블록 하나가 카메라 한 대입니다. 블록을 복사해 값만 바꾸면 카메라가 추가됩니다. `enabled = false`로 두면 수집에서 빠집니다.
- 이 파일은 **CCTV ID ↔ 이름 ↔ 스트림 ID 매핑 기록** 역할도 합니다.

| 항목 | 의미 |
|---|---|
| `cctv_id` | UTIC 공식 CCTV 번호 (예: `L020172`). 파일명에 쓰입니다. |
| `name` / `agency` | 카메라 이름 / 영상 제공 기관 |
| `stream_id` | 영상 주소를 만드는 스트림 ID (예: `L204`). 공식 파일에 없어서 **사람이 브라우저로 확인해 적습니다.** |
| `url` | 실제 HLS 영상 주소 |
| `lon` / `lat` | 경도 / 위도 |

> 연속 실패 경고가 뜨면 UTIC 사이트에서 해당 CCTV를 열어 스트림 ID가 바뀌었는지 확인하고, `stream_id`와 `url`을 고친 뒤 스크립트를 다시 실행하세요.

### `__pycache__\`
Python이 실행 속도를 높이려고 자동으로 만드는 캐시 폴더입니다. 신경 쓰지 않아도 되고, 지워도 다시 생깁니다.

## `TestPic\`: 수집 결과

### 이미지 파일
| 형식 | 예시 | 설명 |
|---|---|---|
| `CCTVID_YYYYMMDD_HHMM.jpg` | `L020172_20260915_2350.jpg` | 정규 수집 이미지입니다. 시각은 실제 촬영 시각이 아니라 **예정 시각**(10분 단위)입니다. |
| `CCTVID_YYYYMMDD_HHMMSS_test.jpg` | `L020172_20260915_233344_test.jpg` | `--once` 테스트 이미지입니다. 시각은 실제 촬영 시각입니다. 정규 데이터가 아니므로 분석할 때 제외합니다. |

- 야간 이미지도 거르지 않고 모두 저장합니다.
- 같은 이름의 파일이 이미 있으면 절대 덮어쓰지 않습니다.

### `logs\capture_log.csv`: 회차별 기록
카메라별로 회차마다 한 줄씩 쌓입니다. 엑셀에서 한글이 깨지지 않도록 UTF-8(BOM)으로 저장됩니다.

| 열 | 의미 |
|---|---|
| `scheduled_at` | 예정 시각 (`--once` 테스트는 빈칸) |
| `captured_at` | 실제 촬영 시각 (또는 마지막 시도 시각) |
| `cctv_id` | CCTV ID |
| `result` | `success` 성공 / `fail` 실패 / `skipped` 건너뜀 / `test` 1회 테스트 |
| `file_name` | 저장된 파일명 (실패 시 빈칸) |
| `attempts` | 접속 시도 횟수 (최대 3) |
| `elapsed_sec` | 소요 시간(초) |
| `error` | 실패·건너뜀 사유 |

- **수집률** = `result`가 `test`가 아닌 행 중 `success` 행의 비율
- ⚠️ 수집 중에 이 파일을 엑셀로 **직접 열어두면** 파일이 잠겨 기록이 누락될 수 있습니다. 확인할 때는 **복사본**을 여세요.

### `logs\collector.log`: 텍스트 로그
스크립트 시작·종료, 회차 시작, 성공·실패, 연속 실패 경고, 복구, 예외 상세 내용이 시간순으로 쌓입니다. 문제가 생겼을 때 원인을 찾는 용도입니다.

```bash
# 경고·에러만 골라 보기
Select-String -Path C:\26_2_AICapstone\TestPic\logs\collector.log -Encoding UTF8 -Pattern '경고|복구됨|ERROR|건너뜀'
```
