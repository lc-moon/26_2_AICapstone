# 프로젝트 — AI 영상인식 기반 미세먼지 예측 및 3차원 시각화

> 프로젝트가 무엇이고 어떤 데이터를 쓰는가. 배경과 명세를 담는다.
> 현재 진행 상태는 `현황.md`, 시점별 기록은 `기록/`을 볼 것.

## 1. 프로젝트 개요

**목표**: CCTV 하늘/원경 이미지를 입력받아 해당 시점의 PM2.5 농도를 추정하는 모델을 학습하고, 결과를 3차원 공간에 시각화한다.

**핵심 가설**: 대기 중 입자에 의한 빛 산란은 관측 거리가 길수록 누적된다. 따라서 원거리 피사체(먼 건물, 산, 트인 하늘)의 대비 저하 정도가 미세먼지 농도의 시각적 신호가 된다.

**산출물**
- 주: 이미지 → PM2.5 농도 예측 모델
- 부: 예측 결과의 3D 시각화 (CesiumJS 검토 중)

**과제 정보**
- 인하공업전문대학 컴퓨터시스템공학과, 2026-2학기 캡스톤디자인 (2학점)
- 기업 제안 주제이며 제안서/결과보고서를 기업에서 제공받음
- 팀 3인 (팀장 겸 AI 모델 담당 / 프론트·백엔드 / 시각화)
- **실질 마감: 2026-11-11 교내 전시회**

## 3. 데이터 소스 명세

### 3.1 CCTV 영상

**ITS 국가교통정보센터** — 고속도로/국도

```
GET https://openapi.its.go.kr:9443/cctvInfo
  apiKey    : 인증키
  type      : ex(고속도로) | its(국도)
  cctvType  : 1(실시간 스트리밍)
  minX,maxX : 경도 범위
  minY,maxY : 위도 범위
  getType   : json
```

응답 필드 (확인됨)

```json
{"response":{"coordtype":1,"data":[
  {"roadsectionid":"","coordx":127.09706,"coordy":37.40665,
   "cctvresolution":"","filecreatetime":"","cctvtype":1,
   "cctvformat":"HLS","cctvname":"[수도권제1순환선] 판교분기점",
   "cctvurl":"http://cctvsec.ktict.co.kr/1/<암호화 토큰>"}]}}
```

- `cctvformat`은 HLS. ffmpeg 또는 OpenCV로 프레임 추출
- `coordx`=경도, `coordy`=위도 (WGS84, `coordtype:1`)
- `roadsectionid`, `cctvresolution`, `filecreatetime`은 빈 값으로 옴
- **월 1,000건 한도**. 좌표 범위 1회 호출로 그 안의 모든 카메라가 반환되므로, 카메라 수가 늘어도 호출 수는 증가하지 않음
- `cctvurl`에 암호화 토큰이 붙어 있어 **만료 가능성 높음**. 만료 주기는 미측정 — 갱신 주기 설계 전에 반드시 실측할 것

**인천교통정보센터(fitic)** — 현재 수집에 쓰는 소스. 인천 전역만 제공한다.
지도 페이지 내부 엔드포인트로 **카메라 목록·좌표·스트림 주소를 한 번에 받을 수 있다**(`현황.md` §3).
UTIC은 이제 수집에 쓰이지 않으며 공식 CCTV 번호·기관명 등 출처 표기용으로만 남는다.

주의: UTIC/ITS 모두 **지도 화면에 보이는 카메라와 API 목록이 일치하지 않는다.** UTIC은 자사 사업으로 설치한 지자체 CCTV만 목록 API로 제공하며, 지도에는 타 지자체 영상도 함께 표시된다. 카메라를 추가할 때는 반드시 API 목록 대조를 거칠 것.

### 3.2 PM2.5 정답값 — 에어코리아

```
Base: https://apis.data.go.kr/B552584/ArpltnInforInqireSvc
```

- 기능: 측정소별 실시간 측정정보 조회(주력), 시도별 실시간, 통합대기환경지수 나쁨이상 목록, 대기질 예보통보, 초미세먼지 주간예보
- 제공 항목: PM10, PM2.5, O3, NO2, CO, SO2, 통합대기환경지수
- **1시간 단위 갱신**
- **개발계정 일 500건 한도** — 측정소 1곳을 1시간 간격으로 호출하면 24건/일이라 여유 있음. 다중 측정소 × 짧은 주기는 금방 소진되므로 주의
- 라이선스: 공공누리 제3유형 (출처표시 + 변경금지)
- 과거 조회는 **3개월까지**(`dataTerm=3MONTH`). 약관상으로도 3개월이 상한(`현황.md` §3)
- `dataTime`은 **끝 시각 표기**다. 12:00 값은 11:00~11:59의 1시간 값(`현황.md` §6)
- 장기 과거 데이터는 "최종확정 측정자료" 파일 데이터로 별도 제공

**측정소정보 API** (별도 서비스)
- 측정소 목록 조회 / 근접측정소 목록 조회 / TM 기준좌표 조회
- 좌표를 넣으면 최근접 측정소와 거리를 반환 → CCTV-측정소 자동 매칭에 사용
- 측정소 목록 조회(`getMsrstnList`)는 **위경도를 그대로 반환**한다(`dmX`=위도, `dmY`=경도). TM은 근접측정소 조회 쪽 얘기
- `mangName`으로 도시대기/도로변대기/항만/교외가 구분됨. **지역 대표 농도는 도시대기**

### 3.3 기상 보조변수 — 기상청 API허브 AWS 매분자료

**학습용 기상값은 이것을 쓴다**(2026-10-01 결정). 사진 시각과 같은 분의 관측값을 소급해서 받는다.

```
GET https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-aws2_min
  tm1, tm2   YYYYMMDDHHMI (KST). 1개 지점이면 하루 이내, 전체 지점이면 10분 이내
  stn        지점번호
  authKey    KMA_HUB_KEY

GET https://apihub.kma.go.kr/api/typ01/url/stn_inf.php?inf=AWS     지점 목록·위경도
```

- 제공: 1분 평균 기온(`TA`)·상대습도(`HM`)·풍향풍속, **강수감지(`RE`, 1분 단위 0/1)**, 15분·60분 누적 강수량
- 응답은 공백 구분 텍스트. **-50 이하는 결측**
- **소급 조회 가능** — 2020-01-01까지 실측 확인. 하루 20,000건이라 4개월 × 관측소 8곳(약 1,000건)도 여유
- **관측소마다 센서가 다르다.** 습도나 강수감지가 없는 곳이 있으므로
  카메라 매칭은 **기온·습도·강수감지를 모두 갖춘 관측소 중 최근접**으로 한다(`현황.md` §8)
- 예보 API(초단기예보·단기예보)는 쓰지 않는다. 예측값이 학습 데이터에 섞이면 라벨이 오염된다

**초단기실황(`getUltraSrtNcst`)** — 수집기가 9/21부터 매시 받아 온 자료다.
격자값이 관측소 한 곳의 정각 1분값과 같다는 것을 확인했으므로(13격자 전부) 위 API의 부분집합이다.
과거 조회가 1일치뿐이라 상시 수집했지만, **학습에는 쓰지 않는다.**

용도:
- **습도** — 안개/박무 구간 식별. 고습도일 때는 미세먼지가 낮아도 영상이 뿌옇게 보이므로, 이를 걸러내지 않으면 모델이 "뿌옇다 = 고농도"를 잘못 학습한다
- **강수** — 렌즈 물방울로 이미지가 훼손되는 구간 제외

## 4. 데이터 스키마

수집 결과는 이미지 파일 + `data/labels/labels.csv`(사진 1장 = 1행)로 축적한다.
`Tools/build_labels.py`가 수집 로그에서 만든다. 값이 없으면 빈칸이다.

| 컬럼 | 출처 | 비고 |
|---|---|---|
| camera_id | 설정 | 카메라 번호 |
| image | 수집기 | `data/images/` 기준 상대 경로. 파일명 HHMM은 회차 시각 |
| captured_at | 수집기 | **실제 촬영 시각**(초). 회차보다 최대 수 분 늦다. 아래 값은 전부 이 시각 기준 |
| sun_alt | 계산 | 태양고도(도). 수집기와 같은 식 |
| pm25 | 에어코리아 | **정답 라벨.** 촬영 시각이 속한 1시간의 값 |
| pm10 | 에어코리아 | 부수 수집 |
| pm_station | 에어코리아 | 최근접 도시대기 측정소 |
| pm_time | 에어코리아 | 붙인 값의 `dataTime`(끝 시각). 11:21 사진이면 12:00 |
| temperature | 기상청 AWS | 촬영한 분의 1분 평균 기온 |
| humidity | 기상청 AWS | 촬영한 분의 1분 평균 습도. 필터/보조변수 |
| wind_speed | 기상청 AWS | 촬영한 분의 1분 평균 풍속 |
| rain | 기상청 AWS (`RE`) | 촬영한 분의 강수감지(0/1). 필터용 |
| aws_station | 기상청 AWS | 기온·습도·강수감지를 갖춘 최근접 관측소 번호 |

카메라별 관측소·측정소와 거리는 `data/labels/stations.csv`에 따로 남는다.

## 5. 단계별 계획

### Phase 1 — 수집 파이프라인

이미지·기상 수집과 장애 알림, 다중 카메라 구조는 완료됐다. 남은 것은 라벨 쪽이다.

1. ~~**labels.csv 병합 배치**~~ — `Tools/build_labels.py`로 완료(2026-10-01). PM2.5 3개월 상한 안에 주기적으로 다시 돌린다
2. **PM2.5 백필** — 3개월 소급이 되므로 상시 수집 대신 주기적 배치로. 약관상 3개월이 상한이라 월 1회는 필수
3. **저장소 관리** — GCS 동기화와 로컬 정리. 디스크가 차면 수집이 조용히 실패한다

### Phase 2 — 데이터셋 구축

7. **필터링 규칙** — 야간(태양고도 기준), 강수, 고습도, 결측 라벨 구간 제외
8. **이미지 전처리** — ROI 크롭(하늘/원경 영역만), 리사이즈, 정규화
9. **데이터 분포 점검** — 농도 구간별 샘플 수 확인. 가을철이라 고농도 샘플 부족이 예상되는 구조적 문제가 있음
10. **외부 데이터셋 병합** — 확보 시. 촬영 시각과 PM2.5 실측 라벨이 있어야 사용 가능.
    고정 카메라이고 같은 카메라 안에 저농도·고농도가 함께 있어야 한다. 후보와 상태는 `현황.md` §5

### Phase 3 — 모델

세부 계획(거르기·ROI·평가 시험지·외부 데이터 결합 방식)은 `현황.md` §7. 학습은 로컬 GPU에서 한다.

11. **베이스라인** — 이미지 통계(대비, 채도, 암채널 등) 기반 회귀. 딥러닝 대비 성능 기준선이자 가설 검증
12. **CNN 회귀 모델** — ConvNeXt V2-Tiny 등 사전학습 백본 + 회귀 헤드. 색·밝기 증강은 쓰지 않는다
13. **기상 보조변수 결합** — 이미지 특징 + 습도/기온을 함께 입력하는 구조
14. **평가** — 날짜 단위 분할. MAE/RMSE, 농도 구간별 오차, 시간대별 오차. 단순 평균 예측 대비 개선폭을 반드시 함께 제시할 것.
    외부 데이터는 학습에만 쓰고 인천 시험지로 평가한다

### Phase 4 — 시각화 및 통합

15. **추정기** — 수집기와 별도 프로세스로 VM에서 20분마다 추정 → 백엔드 전송. 재학습은 로컬에서 주기적으로
16. **야간 표시** — 사진이 없으므로 측정소 실측값 IDW 보간. CCTV 추정과 구분 표시
17. **3D 시각화** — CesiumJS 기반. 더미 데이터로 먼저 구축 가능
18. **전시회용 데모** — 11/11 기준. 실시간 동작 시연 형태

## 6. 기술적 제약 및 주의사항

- **과거 CCTV 영상은 어디에도 없다.** 모든 기관이 실시간 스트림만 제공한다. 지금 수집을 멈추면 그 시간대 데이터는 영구 손실이다. 수집 가동률이 곧 데이터셋 크기다.
- **인증키는 절대 커밋하지 말 것.** 저장소가 public이다. `.env` + `.gitignore` 필수.
- **PTZ(회전형) 카메라는 사용 불가.** 화각이 바뀌면 동일 지점 관측이 성립하지 않는다.
- **야간 이미지는 태양고도 기준으로 제외.** 조명 조건이 달라 동일 모델로 처리 불가.
- **출처 표기 의무** — 결과물과 발표자료에 반영해야 한다.
  - CCTV 영상: 인천교통정보센터
  - 대기오염 정보: 환경부/한국환경공단 에어코리아, 공공누리 제3유형(출처표시 + 변경금지)
  - 에어코리아 자료는 **"인증을 받지 않은 실시간자료"**임을 명시 (이용약관 제8조)
  - 모델 추정값·IDW 보간값은 우리가 계산한 값임을 표시 (`현황.md` §9)
- **에어코리아 운영계정** — 지금은 개발계정. 신청 후 1년 안에 운영계정으로 전환하지 않으면 이용이 제한될 수 있다(약관 제11조 ④). 서비스를 계속 운영할 때만 해당
- 팀 역할: 팀장이 AI 모델(전처리·학습·평가), 나머지 두 명이 프론트·백엔드·시각화 담당
- 선행 과제 보고서 내용을 발표할 때는 **한국건설기술연구원 사업 결과임을 밝힌다**(보고서 주의사항). 원본 PDF는 내부 문서라 저장소에 올리지 않는다

## 7. 선행연구

### 7.1 건설연 "AI 영상인식 기반 3차원 미세먼지정보 통합시스템 시작품 제작" (2022)

교수님께 받은 문서 2개(2026-10-13 확인, 원본은 팀장 PC `OneDrive\문서\카카오톡 받은 파일\`). 제안서는 대부분 그림이고 결과 수치는 최종보고서에 있다.

| 항목 | 내용 |
|---|---|
| 주관 / 수행 | 한국건설기술연구원 / (주)이안에스아이티(위탁), 2022.04~12 |
| 대상 | 고양 일산(킨텍스 근처) CCTV **1대** 중심, 안양은 3차원 시각화 |
| 정답 | 카메라 근처에 **직접 설치한 센서의 1분 PM2.5** |
| 데이터 | 1분 1장, 약 17.8만 장(이후 등급 비율을 맞춰 10만 장). 학습·검증·시험 6:2:2 — **날짜 단위 분할인지는 적혀 있지 않다** |
| 입력 | ROI 사진 + 기상(온도·습도·풍속) + 태양고도 — 우리와 같은 구성 |
| 모델 | ResNet-18 회귀 → **ResNet-152 "분류 모델"**로 PM2.5 수치를 냄(값마다 칸으로 본 것으로 추정). EfficientNet-B4보다 나음 |
| 지표 | 수치 정확도(정확히 맞힌 비율로 추정) 약 43%, RMSE 약 4.3, MAPE 약 21%, **4등급 정확도 약 92%** |
| ROI | 먼 건물·돔 위의 **아주 작은 정사각형 3개**(#2~#4)를 손으로 지정, 2022년 4월·7월 두 번 다시 고름. "설치 센서와 가깝다고 판단되는 영역" |

단계별 비교(같은 보고서 표 3-1~3-5): 전이학습 없음이 있음보다 나음(ResNet-50, RMSE 6.26 대 8.98) → ResNet-152 선택(4.42) →
등급 비율 맞추기(4.25) → **ROI 재선정 후 RMSE 4.25 → 5.53, 4등급 95.5% → 90.8%로 나빠졌지만 채택**(학습 횟수도 30 대 50으로 다름) → 사진 잡음(MAD) 보정(4.25).
표 제목과 본문 수치가 어긋난 곳이 있다(표 3-3~3-5 제목이 모두 "ROI 지정 방법별", 4등급 97.86% 대 95.47%).

**우리와 비교할 때** (10/13 정리)
- "ROI 선정이 오차를 가장 크게 줄였다"는 이 보고서에서 확인되지 않는다. 오히려 ROI 재선정 뒤 일부 지표가 나빠졌고, 우리도 ROI 효과가 0.1 안팎이었다
- 그들은 카메라 1대·등급 중심·분할 방식 미기재, 우리는 카메라 20대·숫자 회귀·**날짜 단위 평가**. 1분 간격 사진을 무작위로 나눴다면 옆 사진이 학습과 시험에 같이 들어가 점수가 부풀려진다
- 4등급 정확도는 등급 분포에 크게 좌우된다(인천은 '좋음'이 71%). 그래서 숫자(92% 대 우리 84%)를 나란히 놓고 비교하지 않는다(`현황.md` §7)

- PM2.5 Concentration Estimation in Single Hazy Images Using Luminance–Spatial Decoupling(Remote Sensing 2026, doi 10.3390/rs18101560): 베이징·상하이 고정 카메라. 우리 베이징 데이터와의 관계는 미확인
