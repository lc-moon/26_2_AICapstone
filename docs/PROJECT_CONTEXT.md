# 프로젝트 컨텍스트 — AI 영상인식 기반 미세먼지 예측 및 3차원 시각화

> Claude Code 인수인계용 문서. 작업 시작 전 이 파일을 먼저 읽을 것.
> 마지막 갱신: 2026-09-20

---

## 1. 프로젝트 개요

**목표**: CCTV 하늘/원경 이미지를 입력받아 해당 시점의 PM2.5 농도를 추정하는 모델을 학습하고, 결과를 3차원 공간에 시각화한다.

**핵심 가설**: 대기 중 입자에 의한 빛 산란은 관측 거리가 길수록 누적된다. 따라서 원거리 피사체(먼 건물, 산, 트인 하늘)의 대비 저하 정도가 미세먼지 농도의 시각적 신호가 된다.

**산출물**
- 주: 이미지 → PM2.5 농도 예측 모델
- 부: 예측 결과의 3D 시각화 (CesiumJS 검토 중)

**과제 정보**
- 인하공업전문대학 컴퓨터시스템공학과, 2026-2학기 캡스톤디자인 (2학점)
- 기업 제안 주제이며 제안서/결과보고서를 기업에서 제공받음
- 팀 3인: 임채문(팀장, AI 모델 담당), 승진, 금혁
- **실질 마감: 2026-11-11 교내 전시회**

## 3. 데이터 소스 명세

### 3.1 CCTV 영상

**ITS 국가교통정보센터** — 고속도로/국도

```
GET https://openapi.its.go.kr:9443/cctvInfo
  apiKey    : 인증키
  type      : ex(고속도로) | its(국도)
  cctvType  : 1(실시간 스트리밍)
  minX,maxX : 경도 범위
  minY,maxY : 위도 범위
  getType   : json
```

응답 필드 (확인됨)

```json
{"response":{"coordtype":1,"data":[
  {"roadsectionid":"","coordx":127.09706,"coordy":37.40665,
   "cctvresolution":"","filecreatetime":"","cctvtype":1,
   "cctvformat":"HLS","cctvname":"[수도권제1순환선] 판교분기점",
   "cctvurl":"http://cctvsec.ktict.co.kr/1/<암호화 토큰>"}]}}
```

- `cctvformat`은 HLS. ffmpeg 또는 OpenCV로 프레임 추출
- `coordx`=경도, `coordy`=위도 (WGS84, `coordtype:1`)
- `roadsectionid`, `cctvresolution`, `filecreatetime`은 빈 값으로 옴
- **월 1,000건 한도**. 좌표 범위 1회 호출로 그 안의 모든 카메라가 반환되므로, 카메라 수가 늘어도 호출 수는 증가하지 않음
- `cctvurl`에 암호화 토큰이 붙어 있어 **만료 가능성 높음**. 만료 주기는 미측정 — 갱신 주기 설계 전에 반드시 실측할 것

**인천교통정보센터(fitic)** — 현재 수집 대상 21대가 이 소스.
지도 페이지 내부 엔드포인트로 **카메라 목록·좌표·스트림 주소를 한 번에 받을 수 있다**(`인수인계.md` §3-2).
UTIC은 이제 수집에 쓰이지 않으며 공식 CCTV 번호·기관명 등 출처 표기용으로만 남는다.

주의: UTIC/ITS 모두 **지도 화면에 보이는 카메라와 API 목록이 일치하지 않는다.** UTIC은 자사 사업으로 설치한 지자체 CCTV만 목록 API로 제공하며, 지도에는 타 지자체 영상도 함께 표시된다. 카메라를 추가할 때는 반드시 API 목록 대조를 거칠 것.

### 3.2 PM2.5 정답값 — 에어코리아

```
Base: https://apis.data.go.kr/B552584/ArpltnInforInqireSvc
```

- 기능: 측정소별 실시간 측정정보 조회(주력), 시도별 실시간, 통합대기환경지수 나쁨이상 목록, 대기질 예보통보, 초미세먼지 주간예보
- 제공 항목: PM10, PM2.5, O3, NO2, CO, SO2, 통합대기환경지수
- **1시간 단위 갱신**
- **개발계정 일 500건 한도** — 측정소 1곳을 1시간 간격으로 호출하면 24건/일이라 여유 있음. 다중 측정소 × 짧은 주기는 금방 소진되므로 주의
- 라이선스: 공공누리 제3유형 (출처표시 + 변경금지)
- 과거 조회 가능 범위는 **미확인**. 기간 옵션을 바꿔가며 실측 필요
- 장기 과거 데이터는 "최종확정 측정자료" 파일 데이터로 별도 제공

**측정소정보 API** (별도 서비스)
- 측정소 목록 조회 / 근접측정소 목록 조회 / TM 기준좌표 조회
- 좌표를 넣으면 최근접 측정소와 거리를 반환 → CCTV-측정소 자동 매칭에 사용
- 측정소 목록 조회(`getMsrstnList`)는 **위경도를 그대로 반환**한다(`dmX`=위도, `dmY`=경도). TM은 근접측정소 조회 쪽 얘기
- `mangName`으로 도시대기/도로변대기/항만/교외가 구분됨. **지역 대표 농도는 도시대기**

### 3.3 기상 보조변수 — 기상청

```
GET http://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst
  base_date, base_time, nx, ny
```

- **반드시 "초단기실황"을 사용할 것.** 초단기예보/단기예보는 예측값이며 학습 데이터에 섞이면 라벨이 오염된다
- 제공: 습도(REH), 기온(T1H), 풍속/풍향, 강수형태(PTY), 1시간 강수량
- **위경도가 아니라 기상청 전용 격자좌표(nx, ny)** 필요. 변환 함수는 `Collector/weather.py`에 구현·검증 완료
- **과거 조회는 1일치뿐** — 백필 불가라 이미지와 함께 상시 수집해야 함
- 개발계정 일 10,000건

용도:
- **습도** — 안개/박무 구간 식별. 고습도일 때는 미세먼지가 낮아도 영상이 뿌옇게 보이므로, 이를 걸러내지 않으면 모델이 "뿌옇다 = 고농도"를 잘못 학습한다
- **강수** — 렌즈 물방울로 이미지가 훼손되는 구간 제외

## 4. 데이터 스키마

수집 결과는 이미지 파일 + labels.csv 형태로 축적한다.

| 컬럼 | 출처 | 비고 |
|---|---|---|
| timestamp | 캡처 시각 | 정시 기준으로 정규화 |
| camera_id | 설정 | 카메라 식별자 |
| image_path | 수집기 | 상대 경로 |
| pm25 | 에어코리아 | **정답 라벨** |
| pm10 | 에어코리아 | 부수 수집 |
| station | 에어코리아 | 측정소명 |
| humidity | 기상청 | 필터/보조변수 |
| temperature | 기상청 | |
| wind_speed | 기상청 | |
| precip_type | 기상청 | 필터용 |
| solar_altitude | 계산 | 좌표+시각으로 산출 (pvlib 등), API 불필요 |

**시각 정렬 주의**: 에어코리아는 1시간 단위, 이미지는 10분 단위로 수집되고 있다. 갱신 지연도 서로 다르므로, 이미지 캡처 시점에 해당 시각의 PM2.5가 아직 게시되지 않았을 수 있다. 라벨 병합은 수집과 분리된 후처리 단계로 두고, 나중에 채워 넣는 구조가 안전하다.

## 5. 앞으로 개발할 것

### Phase 1 — 수집 파이프라인 완성 (최우선)

현재 이미지만 쌓이고 있다. **라벨이 없는 이미지는 학습에 쓸 수 없다.**

1. **에어코리아 수집기** — 1시간 단위 PM2.5 저장
2. **기상청 수집기** — 초단기실황(습도/기온/풍속/강수) 저장. 위경도 → 격자좌표 변환 함수 포함
3. **labels.csv 병합 스크립트** — 이미지와 측정값을 시각 기준으로 결합. 이미지 수집과 분리된 배치로 구성
4. **장애 알림** — 수집이 조용히 멈추는 것이 최대 리스크. 실패 시 알림(로그 파일 + 간단한 알림 수단) 필수
5. **스트림 URL 만료 대응** — 만료 주기 실측 후, 갱신 주기를 결정하고 재시도 로직 추가
6. **다중 카메라 확장** — 설정 파일에 카메라를 추가하면 수집이 늘어나는 구조로 리팩터링

### Phase 2 — 데이터셋 구축

7. **필터링 규칙** — 야간(태양고도 기준), 강수, 고습도, 결측 라벨 구간 제외
8. **이미지 전처리** — ROI 크롭(하늘/원경 영역만), 리사이즈, 정규화
9. **데이터 분포 점검** — 농도 구간별 샘플 수 확인. 가을철이라 고농도 샘플 부족이 예상되는 구조적 문제가 있음
10. **외부 데이터셋 병합** — 확보 시. 촬영 시각과 PM2.5 실측 라벨이 있어야 사용 가능

### Phase 3 — 모델

11. **베이스라인** — 이미지 통계(대비, 채도, 암채널 등) 기반 회귀. 딥러닝 대비 성능 기준선 확보용
12. **CNN 회귀 모델** — ConvNeXt V2-Tiny 등 사전학습 백본 + 회귀 헤드 검토 중
13. **기상 보조변수 결합** — 이미지 특징 + 습도/기온을 함께 입력하는 구조
14. **평가** — MAE/RMSE, 농도 구간별 오차, 시간대별 오차. 단순 평균 예측 대비 개선폭을 반드시 함께 제시할 것

### Phase 4 — 시각화 및 통합

15. **예측 API 서버** — 이미지 입력 → 농도 반환
16. **3D 시각화** — CesiumJS 기반. 더미 데이터로 먼저 구축 가능
17. **전시회용 데모** — 11/11 기준. 실시간 동작 시연 형태

## 6. 기술적 제약 및 주의사항

- **과거 CCTV 영상은 어디에도 없다.** 모든 기관이 실시간 스트림만 제공한다. 지금 수집을 멈추면 그 시간대 데이터는 영구 손실이다. 수집 가동률이 곧 데이터셋 크기다.
- **인증키는 절대 커밋하지 말 것.** 저장소가 public이다. `.env` + `.gitignore` 필수.
- **PTZ(회전형) 카메라는 사용 불가.** 화각이 바뀌면 동일 지점 관측이 성립하지 않는다.
- **야간 이미지는 태양고도 기준으로 제외.** 조명 조건이 달라 동일 모델로 처리 불가.
- **출처 표기 의무** — UTIC은 경찰청 도시교통정보센터 명시, 에어코리아는 공공누리 3유형(출처표시+변경금지). 결과물과 발표자료에 반영 필요.
- 팀 역할 전환 예정: 임채문이 AI 모델(전처리/학습/평가), 승진·금혁이 프론트/백/시각화 담당.
