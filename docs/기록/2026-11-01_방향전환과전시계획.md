## 요약

- 10/29 시연 피드백은 "예측값이 어떻게 나왔는지 없다", "무슨 서비스인지 애매하다", "왜 써야 하는지 설득이 없다", "표면상 주제와 다르게 갔다"였다
- 사용자가 생활권 서비스는 수요가 없다고 스스로 결론 냈고, **"도로 CCTV로 PM2.5를 읽을 수 있는가"를 검증한 프로젝트**로 방향을 바꿨다. 지도는 실제로 돌아간다는 증거이자 결과 화면이 된다
- 전시 준비 계획 `docs/전시_준비.md`를 만들었다: 모델 M0~M7, 서비스 S1~S10, 전시물 E. 역할은 팀장 = 모델·추정기, 승진 = 백엔드, 금혁 = 프론트 그대로
- 모델 쪽은 **시험 데이터 10/20~11/1 하나로 모든 후보를 채점**하고, 비교군 ⓐ~ⓖ를 미리 정했다. ⓑ(같은 방법, 날 수만 늘림)를 대조군으로 넣었다
- 서버 추정기 2주 실측 대조: MAE 4.05, 치우침 +2.2. 비 거르기를 고친 뒤(10/19~27)는 3.61, +1.4

## 배경 — 시연에서 "어떻게 나왔는지"가 비어 있었다

10/29 시연까지는 배포가 목표였다(10/26~27 기록). 지도는 돌아갔지만, 숫자가 어디서 나왔는지와 이 서비스가 왜 필요한지를 보여 주지 못했다.

인천은 측정소가 내륙에만 20곳이라 촘촘하다. 그래서 "측정소 대신 CCTV"는 소비자 서비스로 설득하기 어렵다. 게다가 과제 주제("AI 영상인식 기반 미세먼지 예측")가 원래 연구 질문에 가깝다.

## 한 일

### 방향 바꾸기

- 전시와 발표는 **질문 → 가설 → 데이터 → 방법 → 결과 → 한계** 흐름으로 한다
- 주인공은 원리 설명·Grad-CAM·실시간 실측 대조·직접 해보기다. 지도는 결과 화면이다
- 서비스 부가기능(시간 막대 애니메이션, 휴대폰 2D판)은 전시 뒤로 뺐다
- 검증하지 않은 장점(고농도, 다른 도시 이식, 측정소보다 빠름)은 내세우지 않는다

### 전시 형태

- 노트북에 서비스를 띄워 두고 관람객이 직접 만진다. TV에는 소개 영상을 반복 재생한다
- 해가 진 뒤에도 전시가 되게, 실서비스(밤 = 측정소 실측)와 별도로 **전시용 링크(S10)**를 둔다. 그날 마지막 낮 회차를 보여 준다
- 사진 규칙: 모델이 보는 위쪽 60%만 그대로, 아래 40%는 **굵은 모자이크**로 한다. "원본 → ROI → 모델" 과정이 보이도록 도로 모양은 남기고, 차량·번호판은 알아볼 수 없게 한다. 가리는 일은 서버에서 한다(브라우저에서 가리면 원본이 내려간다)

### 모델 계획 (M0~M7)

- 시험 데이터는 **10/20~11/1 하나**로 모든 후보를 채점한다. 학습은 9/22~10/19
- 비교군:

  | 기호 | 후보 |
  |---|---|
  | ⓐ | 지금 서비스 모델 |
  | ⓑ | 같은 방법으로 10/19까지 다시 학습 |
  | ⓒ | 카메라별 보정 |
  | ⓓ | 카메라별 미세조정 |
  | ⓔ | 공통 몸통 + 카메라별 마지막 층 |
  | ⓕ | 습도 |
  | ⓖ | 일사량·운량 |

- **ⓑ를 넣은 이유**: ⓒ~ⓖ가 좋아져도, 그게 방법 덕인지 날 수가 늘어난 덕인지 가를 대조군이 필요하다(`docs/전시_준비.md`에 적힌 이유)
- 카메라별 모델(ⓓ)은 교수님 제안이다
- 일사량 1분값은 기상자료개방포털 ASOS 분 자료(로그인, 1회 1일)에만 있다. 10/28에 하루치를 받아 API허브 시간값과 맞는 것을 확인했다. 운량은 정시 1회 시간자료뿐이다(11/1 확인)

## 확인한 것

| 항목 | 결과 |
|---|---|
| 서버 추정기 2주 대조 (10/15 11:25~10/27, 7,428장, 10/28 계산) | MAE 4.05, 치우침 +2.2 |
| 비 거르기 고치기 전 (10/15~18, 2,030장) | 5.23. 10/18 기록 5.21·2,049장과 조금 다르고, 이유는 확인하지 않았다 |
| 고친 뒤 (10/19~27, 5,398장) | **3.61·+1.4**, 하루 2.62~4.87 |

두 기간은 날씨가 다르다. 그래서 줄어든 몫이 전부 비 거르기 수정 효과라고는 하지 않는다.
