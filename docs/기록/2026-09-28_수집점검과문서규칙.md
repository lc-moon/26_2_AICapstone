## 요약

- 수집 이미지를 한 장으로 붙여 보는 **컨택트 시트 도구**를 만들었다. 조원에게 수집 결과를 보여주는 용도다
- 서버의 `weather.csv`를 내려받아 확인했다. **2,106행 = 162시간 × 13격자, 빠진 시간 0, 중복 0**
- Claude Code가 읽는 문서를 점검하다 **코드와 어긋난 곳 4건**을 찾아 고쳤다
- 문서 동기화를 검사기와 hook으로 자동화하려다 **너무 복잡해져 되돌렸다.** 규칙만 CLAUDE.md에 남겼다

## 배경

수집이 일주일째 돌고 있었다. Discord 알림은 계속 왔고, 카메라 몇 대가 가끔 죽었다가 스스로 살아나는
패턴이 반복됐다. 알림만으로는 **사진이 실제로 어떻게 찍히고 기상값이 어떻게 쌓이는지** 보이지 않아서,
조원에게 보여줄 자료가 필요했다.

## 한 일

### 컨택트 시트 — `Tools/contact_sheet.py`

서버에 쌓인 이미지를 한 장씩 내려받아 보면 수백 장이다. 여러 장을 격자로 붙여 한 장으로 만든다.

| 모드 | 내용 |
|---|---|
| `--time` | 한 시각의 카메라 전체 (5열) |
| `--camera` | 한 카메라의 하루 (6열) |

라벨은 카메라 번호와 시각만 적는다. OpenCV가 한글을 그리지 못해서다.
수집기가 `--once`로 만드는 `_test` 폴더가 섞여 있으면 번호 정렬이 깨지므로 숫자 폴더만 고르게 했다.

서버에서 `2026-09-28 12:00` 전체 시트를 만들어 내려받았다.

### 문서 점검

Claude Code가 어떤 문서를 읽는지 정리하다 낡은 곳을 찾았다.

| 위치 | 문제 |
|---|---|
| 메모리 | 9/22에 이름이 바뀐 `PROJECT_CONTEXT.md`, `인수인계.md`를 가리키고 있었다 |
| `README.md` | `weather.py`, `contact_sheet.py`, `make_prototype_data.py`, 인터페이스 문서, `model_output/`이 빠져 있었다 |
| `현황.md` §2 | 용량이 "4개월 18GB". 같은 문서 §3·§7은 이미 실측 22GB |
| `프로젝트.md` §4 | 수집 주기 "10분", `timestamp` "정시 기준 정규화". 실제는 20분 슬롯 |

저장소 루트에 `CLAUDE.md`를 새로 두었다. 세션마다 자동으로 읽히므로
**`Collector/`는 서버가 pull해서 돌린다**, **시각이 어긋난 기상값·PM2.5를 붙이지 않는다**,
**`data/`·`.env`를 올리지 않는다** 같은 어기면 안 되는 규칙을 거기에 모았다.

### 자동화를 만들었다가 되돌렸다

README에서 새 도구가 빠지는 일이 반복돼, 문서 누락을 검사하는 `Tools/check_docs.py`를 만들고
커밋 때 hook으로 돌리는 방안을 검토했다.

**되돌렸다.** 문서 몇 개를 맞추자고 검사기와 hook을 유지하는 것이 더 무거웠다.
CLAUDE.md에 "무엇을 바꾸면 어느 문서를 같이 고치는가" 표만 남기고, 검사기는 지웠다.
이미 푸시한 커밋은 수정 후 `--force-with-lease`로 다시 올렸다.

9/22의 "과하게 만들었다가 되돌렸다"와 같은 실수다. **해결책의 무게를 문제의 크기에 맞추지 않았다.**

### 조원 공유용 정리 (9/29)

조원들이 쓰는 형식(소제목 + 짧은 소개)에 맞춰 지금까지 만든 것을 두 항목으로 줄였다.

- 모델 학습용 CCTV 이미지 자동 수집
- 학습용 기상 데이터 동시 수집

Claude Code로 작업했다는 것이 보이도록, 대화와 코드가 함께 보이는 화면을 항목별로 골랐다.
이미지 수집은 태양고도 계산부, 기상 수집은 위경도→격자 변환부와 정합성 확인 대화다.

## 남은 문제

- **백엔드 조원의 작업과 겹친다.** 조원이 보낸 요약에 기상 수집과 측정소 매칭이 들어 있는데,
  수집기가 이미 하는 일이다. 어느 쪽을 기준으로 할지 정해야 한다
- 기상 부분 실패 알림이 실제로 동작하는지는 실패가 한 번 나야 확인된다
- 고농도 데이터 부재(현황 §5)는 그대로다
