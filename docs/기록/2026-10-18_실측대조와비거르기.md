# 2026-10-18 · 실측 대조와 비 거르기

> 7주차 · 인천 ver로 바꾼 뒤 나흘을 실측과 맞춰 보다 추정기의 비 거르기가 실시간으로는 한 번도 작동하지 않았다는 것을 찾았다.
> 비 판단을 60분 강수량으로 바꿔 배포했고, 더 나은 대안으로 기상청 레이더 강우강도를 조사해 지연·실패율 측정을 걸어 두었다.

## 요약

- 인천 ver 나흘(10/15 11:25~10/18 17:40, 2,049장) 실측 대조 **MAE 5.21, 치우침 +4.2** — 10/14(2.17)보다 크게 나빴다
- 원인 하나는 **버그**였다. 추정기는 1분 자료의 강수 감지(`RE`)로 비를 거르는데, `RE`는 **당일에는 늘 결측이고 다음 날쯤 채워진다**.
  10/18 오후 큰 비(60분 15~40mm) 속 사진 151장이 추정돼 MAE 16.3. → 추정기 비 판단을 **60분 강수량 > 0** 하나로 바꿔 배포
- 다른 하나는 **모델 한계**다. 비 사진을 빼도 치우침 +3.2이고 습할수록 커진다(습도 50% 미만 +0.1 → 70~85% +5.2). 학습 교차검증에는 없던 경향이다.
  모델은 사용자의 새 아이디어와 함께 다시 보기로 해 서비스 모델은 그대로 둔다
- 대안 조사: **레이더 지점별 강우강도(HSP) 0.5 mm/h**가 비 감지 대비 99%를 잡았다(60분 강수량 91%). 레이더를 주로, 60분 강수량을 보조로 가기로 했고
  API 응답이 자주 비어 12시간 지연·실패율 측정을 걸어 두었다. AWS 1분 현천은 우리 관측소 3곳에만 있어 쓰지 않는다

사용자가 세 가지를 모두 해 보자고 했다(4일치 사진 600MB를 VM에서 받음, 비용은 GCP 전송료 100~200원 수준으로 설명).

### 비 판단을 60분 강수량으로

강수량(15분·60분 누적)은 습도와 같이 1~2분 뒤 올라와 추정기의 3분 대기에 맞는다. 학습 때 `RE`로 뺀 사진 229장을 기준으로

| 기준 | 잡은 사진 |
|---|---|
| 60분 강수량 > 0 | 185장 (81%) |
| 15분 강수량 > 0 | 117장 (51%) |

60분은 비가 그친 뒤 최대 1시간도 비로 보지만, 학습 기준(`RE`)에 더 가깝고 젖은 도로·물방울이 남는 시간이라 손해가 작다고 보고 60분을 골랐다.

처음에는 "`RE`가 있으면 쓰고, 없으면 60분 강수량"으로 배포했다. 사용자가 "`RE`는 결국 다음 날에야 쓸 수 있는데 남겨 둘 이유가 있나"를 물었다.
실시간에는 늘 결측이라 그 분기는 쓰이지 않고, 오히려 같은 사진이 처리 시점에 따라 판단이 달라질 수 있었다(10/16 강수량>0·`RE`=0 사진 17장).
사용자는 주석 처리를 제안했는데 Claude가 "지우고 이유만 주석으로, 옛 코드는 git에 있다"를 권했고 그렇게 했다.

60분 강수량이 결측인 경우도 있었다 — 512번 10/5 하루, 649번 10/15 오후(7.5시간). 둘 다 비 감지 0이라 비가 겹친 적은 없었다.
결측이면 추정하지 않는 안을 권했지만, 사용자는 "당장 라이브 서비스를 할 것은 아니니 일단 추정해 두자"고 정했다.

### 레이더와 현천 시험

사용자가 API허브에서 두 API를 신청했다(활용 목적 문구는 Claude가 제안).

- **AWS 1분 현천(`nph-aws2_min_vis`)**: 실시간(21:47:36에 21:47 값). 비 92%를 잡고 오전에는 우량계보다 먼저 안개비(51)를 잡았다.
  그러나 우리 관측소 7곳 중 **112·565·570에만** 있고, 10/16 뿌연 날은 세 곳 모두 '맑음'(박무 0회)이었다 → 사용자 판단 "현천은 못 쓴다"
- **레이더(`nph-rdr_cmp_aws_pt_data`)**: 7곳 모두 값이 있고 5분 간격, 약 7분 지연(두 번 확인).
  - 시각 칸이 32비트 정수로 넘쳐 온다. 2³²를 더해 되돌린다
  - 빈 응답이 잦다. 4개 동시·수백 번 요청하던 중에는 10번 재시도해도 못 받은 시간이 있었는데, 멈추고 다시 요청하니 첫 시도에 왔다.
    조용할 때도 첫 시도 빈 응답이 20번 중 8번이었고, 2~4번째에 모두 왔다(요청당 1~3초)
  - 강우강도(HSP, mm/h)는 반사도(HSR, dBZ) 하나로 계산되는 값이 아니었다(같은 시각 47.1 dBZ → 76.7, 47.5 dBZ → 52.2)

같은 5분 시각끼리 비 감지와 맞췄다(9/25·10/16·10/17, 112·511·512, 779개 시각 중 비 88).

| 기준 | 비 잡음 | 비 감지 0인데 비로 봄 |
|---|---|---|
| 강우강도 > 0 | 100% | 12.0% |
| 0.2 mm/h 이상 | 100% | 9.7% |
| **0.5 mm/h 이상** | **99%** | **4.5%** |
| 1.0 mm/h 이상 | 89% | 1.4% |
| 60분 강수량 > 0 | 91% | 2.9% |

헛걸림은 전부 비 온 9/25에서 나왔고(맑은 10/16·10/17은 0), 0.5 기준 31개 중 13개는 60분 강수량도 0보다 컸다.
사용자는 "비 오는 날에 0.5 mm/h 이상 잡힌 것이면 문제가 될 것 같지 않다"며 **레이더를 주로, 60분 강수량을 보조로** 가기로 했다. 코드는 아직 그대로다.

## 정정된 판단

- **"`RE`는 학습과 같은 기준이니 있으면 쓴다"(Claude, 첫 배포)** → 실시간에는 늘 결측이라 쓰이지 않고 처리 시점마다 판단이 달라질 수 있어 지웠다
- **"레이더 강우강도 판(HSP)은 지금 시각에는 자료가 없다"(Claude)** → 빈 응답을 한 번만 받고 내린 판단이었다. 재시도하니 2023년부터 지금까지 다 나왔다
- **"레이더 20 dBZ 헛걸림 8%"(Claude)** → 10/18을 15분 강수량 기준으로 세어 이슬비를 헛걸림으로 셌다. 비 감지 기준 3일로 다시 세니 2.3%
- **"60분 강수량은 비 감지의 81%"** → 학습 사진 기준. 관측소-분 기준(27일)은 73%로, 같은 사실을 다른 단위로 센 것이다
