> 이날은 구축만 하고 **배포는 하지 않았다.** 실제 가동은 9/21.

## 요약

- GCP에 e2-micro VM을 만들었다. Ubuntu 22.04는 Python 3.10이라 `tomllib`이 없어 24.04로 다시 만들었다
- **$300 무료 크레딧이 없었다.** 실제 가격으로 재계산하니 월 약 $4.4, 그중 **외부 IP가 $3.65로 대부분**이었다
- 클라우드 IP에서도 CCTV 스트림 접속이 되는 것을 두 리전에서 확인했다
- 숭의 측정소 분석에서 **고농도 데이터가 거의 없다**는 구조적 리스크가 드러났다
- 카메라 소스를 정하지 못해 배포는 미루고 VM을 중지 상태로 뒀다

## 배경

2주차 MVP는 테스트가 목적이었으므로 집 데스크탑 터미널에서 돌렸다.
본 수집으로 넘어가려면 이 구조로는 곤란하다.

- 터미널 창이 닫히면 끝나고, PC 절전·재부팅·인터넷 끊김에 그대로 노출된다
- 과거 CCTV 스트림을 제공하는 곳이 없어 **수집 가동률이 곧 데이터셋 크기**다.
  몇 달을 돌려야 하는데 사람이 계속 신경 써야 하는 구조는 맞지 않는다

### 무료 티어 조건

Always Free 조건을 맞춘 구성이며, **하나라도 어긋나면 과금된다.**

- us-west1 / us-central1 / us-east1 중 한 곳
- e2-micro, 비선점형(표준)
- 표준 영구 디스크 30GB 이하
- 결제 계정 전체에서 e2-micro 합산 약 730시간/월

## 확인한 것

### 비용 — 예상과 달랐던 점

**$300 무료 체험 크레딧이 없었다.** 일반 유료 계정으로 발급돼 카드로 직접 청구된다.
그래서 비용을 실제 가격표로 다시 계산했다.

| 항목 | 월 |
|---|---|
| e2-micro + 디스크 30GB | $0 (Always Free) |
| 외부 IPv4 (임시) | **$3.65** ($0.005/시간) |
| GCS 40GB 중 과금분 35GB | 약 $0.75 |
| VM → GCS (동일 리전) | $0 |
| **합계** | **약 $4.4/월** |

VM 자체는 공짜인데 **외부 IP가 비용의 대부분**이라는 게 의외였다.
VM을 중지하면 IP가 반납되어 요금도 멈춘다.

예산 알림을 걸어 일정 비율에서 메일이 오게 했다. (구체적인 프로젝트 식별자는 `_archive/서버정보_비공개.md`)

### 검증한 것

**클라우드 IP에서 CCTV 스트림에 접속할 수 있는가** — 이게 안 되면 계획 전체가 무산되므로 먼저 확인했다.

- 대만(asia-east1, Cloud Shell)과 오리건(us-west1, VM) 두 곳에서 성공
- 해상도도 집 PC와 동일해 저화질 대체 스트림이 아니었다
- → **해외 IP 차단 없음, 데이터센터 IP 차단 없음, Referer 검사 없음**

**UTIC 인증키의 IP 종속 문제는 수집과 무관했다.** 수집 스크립트는 UTIC을 호출하지 않고
인천교통정보센터의 인증 없는 공개 HLS에 직접 접속한다. UTIC은 메타데이터 출처로만 쓰였다.

**PM2.5는 3개월 소급 조회가 된다.** `dataTerm=3MONTH`로 2,207시간을 받아봤다.
라벨을 나중에 배치로 채울 수 있다는 뜻이다.

## 남은 문제

### 드러난 구조적 리스크

숭의 측정소 3개월치를 분석한 결과, **고농도 데이터가 사실상 없다는 것**이 확인됐다.

- 2,148시간 중 '나쁨' 이상이 38시간(1.8%), '매우나쁨' 0시간
- 2026년 9월만 보면 373시간 중 '나쁨' 0건

모델 마감까지 모이는 데이터는 0~35㎍/㎥ 구간뿐이라는 뜻이다.
**외부 데이터셋 조달이 선택이 아니라 필수 항목이 됐다.**

### 끝내지 못한 것

기존 수집기는 `cameras.toml`의 고정 URL 하나를 읽는 구조라 카메라를 늘리면 전제가 깨졌다.
스트림 주소를 브라우저 개발자도구로 직접 캐야 했기 때문이다.

그래서 **카메라 소스를 무엇으로 할지(UTIC 유지 vs ITS 전환)** 를 먼저 정하기로 하고,
VM은 중지 상태로 보관한 채 마무리했다.
