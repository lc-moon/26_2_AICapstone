# 2026-10-10 · 모델 계획과 외부 데이터

> 6주차 · 10/8 발표에서 특별한 피드백이 없어 계획대로 모델 단계로 넘어간다.
> 모델을 만드는 순서와 평가 방법, 완성 후의 서비스 형태를 정했고,
> 고농도를 채울 외부 데이터셋을 실제로 받아 확인했다.

---

## 요약

- 모델은 **인천 데이터 단독으로 먼저** 만든다. 베이스라인(이미지 통계) → CNN → 기상 결합 순서다
- 평가는 **날짜 단위 분할**로 한다. 외부 데이터는 학습에만 쓰고, 고농도 성능은 따로 떼어 둔 "참고 시험"으로만 본다
- 서비스 형태도 정했다. 수집기와 **분리된 추정기**를 VM에 올리고, **밤에는 측정소 실측값을 IDW로 보간**해 보여 준다.
  "수집할 때마다 학습"은 정답이 1시간 뒤에 나오므로 불가하고, **주기적인 재학습**으로 대신한다
- 에어코리아 약관을 원문으로 확인했다. IDW와 모델 값은 금지 조항에 해당하지 않는다고 보고, **"우리가 계산한 값"으로 표시**하기로 했다
- 외부 데이터 후보 11개 중 실제로 받을 수 있는 건 셋이었다. **허산은 받아서 확인(306장, 11~100㎍/㎥)**, 베이징은 받는 중, 톈진은 보류

## 배경

10/8 6주차 발표(피드백 반영, 기상 1분 API 전환, `build_labels.py`)에서는 별다른 피드백이 없었다.
모델 마감(11/11)까지 4주 남짓이라 모델 작업을 시작하기 전에 순서와 형태를 확정해야 했다.
사용자는 AI 모델 담당이지만 모델 설계는 처음이라, 갈림길마다 이유를 듣고 정하는 방식으로 진행했다.

## 한 일

### 모델 만드는 순서

| 단계 | 내용 | 목적 |
|---|---|---|
| 거르기 | 강수(`rain=1`), 고습도(기준은 데이터를 보고 정함), PM2.5 결측, 가려진 화면 | 먼지가 아닌 이유로 흐린 사진 제거 |
| ROI | 하늘·원경 건물만 자른다. 카메라마다 한 번 지정 | 차량·도로 잡음 제거. 산은 단풍 때문에 피한다 |
| 베이스라인 | 대비·채도·암채널·선명도·하늘-원경 밝기차 + 습도·태양고도 → 회귀 | **가설 검증**과 비교 기준선 |
| CNN | 사전학습 백본(ConvNeXt V2-Tiny 등) + 회귀 헤드, 미세조정 | 데이터가 적어 처음부터 학습은 불가 |
| 기상 결합 | 이미지 특징 + 습도·기온·풍속·태양고도 | 같은 흐림이라도 습도가 높으면 먼지 탓이 아닐 수 있다 |

ROI는 처음부터 지정하지 않고 사진 전체로 베이스라인을 먼저 돌려 보기로 했다.
상관이 나오는지부터 보고, ROI는 결과를 본 뒤에 해도 늦지 않다.

CNN에서 짚은 주의점이 하나 있다. 사진 학습에서 흔히 쓰는 **색·밝기 증강은 쓰면 안 된다.**
우리 문제에서는 색과 대비 자체가 정답의 신호라, 그것을 흔들면 정답을 흔드는 셈이다.

### 평가 방법

- **사진을 무작위로 나누지 않는다.** 11:00 사진이 학습에, 11:20 사진이 시험에 들어가면 답을 보고 시험을 치는 셈이다.
  날짜 단위로 나눈다
- 지표는 MAE·RMSE. **늘 평균만 찍는 모델 대비 개선폭**을 반드시 같이 낸다.
  가을이라 농도가 낮은 구간에 몰려 있어 평균만 불러도 MAE가 작게 나올 수 있다
- 정답이 1시간 평균이므로, 같은 시간 사진 3장의 예측을 평균해 비교하는 방식도 같이 본다

### 외부 데이터를 섞는 방식

사용자의 첫 구상은 "인천으로 완성한 모델에 고농도 데이터를 나중에 덧붙여 학습"이었다.
이 순서는 마지막에 본 데이터 쪽으로 쏠려 **인천 장면을 보는 능력이 떨어질 수 있어** 권하지 않았다.

| 방식 | 판단 |
|---|---|
| 인천 → 외부 | 비추천. 인천 성적이 나빠질 수 있다 |
| 외부 → 인천 | 가장 흔한 방식. 인천은 안정적이나 고농도 감각이 흐려질 수 있다 |
| 섞어서 한 번에 | 둘 다 유지하기 좋으나 비율을 맞춰야 한다 |

뒤의 둘 중 무엇이 나은지는 **둘 다 해 보고 숫자로 고른다.** 시험지는 둘이다.

- **A. 인천 시험** — 인천 데이터 중 학습에 안 쓴 날짜. 모든 실험에서 같은 시험지. 본 성적이다
- **B. 고농도 참고 시험** — 외부 데이터 중 학습에 안 쓴 날짜

함정도 하나 정리했다. 외부에 고농도만 있고 인천에 저농도만 있으면, 모델이 흐림이 아니라
**"베이징 건물이면 높다, 인천 건물이면 낮다"를 외울 수 있다.**
그래서 외부 데이터도 같은 카메라 안에 맑은 날과 탁한 날이 함께 있어야 한다.

외부 데이터를 결국 못 구해도 인천 단독 결과만으로 결과물은 완성된다. 그때는 "0~35 범위에서 검증"을 한계로 밝힌다.

### 서비스 형태 — 무엇이 되고 무엇이 안 되나

사용자가 그린 최종 형태는 이렇다. VM에서 20분마다 수집하고 추정해 백엔드로 보내고,
가능하면 수집할 때마다 학습하고, 백엔드 DB에 쌓아 타임라인으로 과거를 넘겨 볼 수 있게 한다.

| 구상 | 판정 | 이유 |
|---|---|---|
| 20분마다 추정해 백엔드로 전송 | 가능 | 형식은 9/22에 정한 `values.json` 그대로 |
| DB에 쌓아 타임라인으로 보기 | 가능 | 숫자 20개 × 하루 30여 회차라 작다 |
| **수집할 때마다 학습** | **불가** | 11:20 사진의 정답(12:00 값)은 12:15쯤 게시된다. 찍는 순간에는 학습할 짝이 없다 |
| 주기적 재학습 | 가능 | 쌓인 데이터로 로컬 GPU에서 학습 → **시험 점수가 나을 때만** VM 모델 교체. 주 1회 정도 |
| VM에서 CNN 추정 | 미확인 | e2-micro 메모리 1GB. ONNX로 가볍게 하거나 VM 사양을 올려야 할 수 있다 |

정답이 늦게 온다는 점은 오히려 기능이 된다. 타임라인에 **그때의 추정값과 나중에 확정된 실측값을 나란히** 보여 줄 수 있다.

추정기는 **수집기와 별도 프로그램**으로 둔다. 수집기 안에 넣으면 추정 쪽 오류로 수집이 멈출 수 있고,
이미지는 놓치면 영구 손실이다. `build_labels.py`를 분리한 것과 같은 원칙이다.

**밤 처리는 사용자가 제안했다.** 밤에는 사진을 안 찍으므로 추정이 불가하니, 측정소 실측값을 IDW로 보간해
빈 격자 없이 보여 준다. 받아들이면서 붙인 조건은 이렇다.

- 낮(CCTV 추정)과 밤(측정소 실측 보간)을 화면에서 구분한다
- 밤 값은 1시간 평균에 15분 늦게 게시되므로 **몇 시 기준인지** 같이 표시한다
- 경계 지역은 경기도 도시대기 측정소도 넣는다
- 밤에 실측 IDW를 보여 주면 "그럼 낮에도 IDW면 되지 않나"는 질문이 나온다.
  인천은 측정소가 촘촘해 공간 이득이 작을 수 있으므로 **"20분 간격, 더 빨리"를 앞세운다**

### 에어코리아 약관 확인

이전에 받아둔 에어코리아 OpenAPI 기술문서(§3.2 준수사항, §3.3 활용약관, 2020-11-26 시행)와 공공누리 공식 페이지로 확인했다.

| 근거 | 내용 | 판단 |
|---|---|---|
| 공공누리 제3유형 | "저작물을 변경하거나 2차적 저작물 등으로 작성할 수 없다". 문제 사례로 통계수치를 수정해 착오를 일으키는 경우를 든다 | 측정값을 고치거나 우리 값을 공식 값처럼 보이게 하지 않으면 된다 |
| 약관 제5조 6호 | 비합리적인 산정방식으로 이용자에게 혼란을 초래하는 행위 금지 | IDW는 표준 방법. 실측처럼 보이게 하면 걸릴 수 있다 |
| 제7조 | 라이선스 표시와 출처(환경부/한국환경공단) 표시 의무 | 화면에 필수 |
| 제8조 | 실시간 데이터는 오류가 있을 수 있음을 표기 | 화면에 필수 |
| 제9조 ③ | 자유롭게 본인이 만든 웹 서비스에 연동할 수 있다 | 서비스 형태는 허용 |
| 제9조 ④ | 사전 승낙 없이 영업활동 금지 | 캡스톤은 해당 없음. 상용화 시 승낙 필요 |

"변경금지"가 숫자 보간에 어떻게 적용되는지는 어느 문서에도 기준이 없다. 회색지대로 남기되,
측정소 값은 그대로 두고 **IDW 격자와 모델 값은 "우리가 계산한 값"으로 표시**하는 것으로 정했다.
포트폴리오용이고 실제 서비스 계획은 없어 문의까지는 하지 않았다.

## 남은 문제

- **인천 1단계 시작.** VM에서 최신 `capture_log.csv`와 이미지를 내려받아 `build_labels.py`를 다시 돌리는 것부터
- 베이징 다운로드가 끝나면 장수·기간, 낮 사진의 농도 분포, 고정 화각인지를 확인한다. 기대대로면 톈진은 받지 않는다
- 백엔드 조원과 정할 것: 추정값 전송 방식, 백엔드·DB를 어디서 돌릴지(e2-micro에 다 올리면 메모리 부족), 저장 항목(나중에 채울 실측값 칸 포함), 밤 화면 표시
- VM에서 CNN 추정이 메모리에 들어가는지는 모델이 나온 뒤 실측한다
- 3개월 상한 조항이 1월 재학습(9~10월 라벨 사용)에도 걸릴 소지가 있다. 포트폴리오 목적이라 크게 보지 않기로 했다
- 수집기 알림 문구("복구 불가")는 그대로다
