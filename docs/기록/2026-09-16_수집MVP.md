## 요약

## 배경

CCTV 영상을 코드로 가져올 수 있는지, 그리고 사람이 지켜보지 않아도 며칠간 돌아가는지를 확인하는 것이 목적이었다.
테스트가 목적이므로 카메라 한 대, 집 데스크탑 터미널 실행으로 시작했다.

## 한 일

### 만든 것

| 파일 | 역할 |
|---|---|
| `check_cctv.py` | **사전 확인용 1회성 프로그램.** 저장된 목록에서 CCTV를 찾고, UTIC 스트림 페이지에서 영상 주소를 추출해 프레임 1장을 저장할 수 있는지 확인 |
| `cctvOpenData_list.html` | UTIC CCTV 목록 페이지 저장본(8.4MB). 차단 기준 때문에 다시 호출하지 않고 저장본 재사용 |
| `OpenDataCCTV.xlsx` | UTIC 공식 CCTV 좌표·속성 파일 (CCTV ID, 센터명, 경도·위도) |
| `collect_cctv.py` | **수집 스크립트.** 정각 기준 10분마다 프레임 1장을 jpg로 저장하고 회차마다 CSV·텍스트 로그를 남김 |
| `cameras.toml` | 설정 파일. 캡처 간격·경로·타임아웃·재시도 규칙과 카메라 목록. CCTV ID ↔ 이름 ↔ 스트림 ID 매핑 기록 역할도 함 |
| `capture_log.csv` | 회차별 기록 (예정 시각, 촬영 시각, 결과, 파일명, 시도 횟수, 소요 시간, 실패 사유) |
| `collector.log` | 텍스트 로그 (시작·종료, 성공·실패, 연속 실패 경고, 복구, 예외) |

### A. 영상 주소 확인 (2026-09-15, 1회만 수행)

```
UTIC 인증 메일로 목록 URL 확보 (cctvOpenData.do?key=***)
  → 목록 페이지(HTML) 1회 저장 → "용현사거리" 검색 → ID L020172 (인천교통정보센터)
  → 공식 좌표 파일(xlsx)에서 좌표 확인 (경도 126.650032, 위도 37.456271)
  → 영상 접속값(ID)이 공식 파일에 없음 → 브라우저 개발자 도구로 확인
       ID = L204, 영상 주소 = https://cctv.fitic.go.kr/cctv/L204.stream/playlist.m3u8 (HLS)
  → check_cctv.py로 프레임 1장 캡처 성공 (960x540, 약 2초)
```

최종 영상 주소에는 **인증키나 토큰이 들어가지 않는다.** 그래서 수집 단계에서는 UTIC 페이지를 호출하지 않고 이 주소에 바로 접속한다.

### B. 10분 단위 수집

```
cameras.toml 읽기·검증 (retry_wait_sec < 10 등은 시작 전에 거부)
  → 다음 정각 10분 단위 시각까지 대기 (KST 고정)
  → [회차 시작] 카메라를 순서대로 하나씩 처리 (동시 접속 없음)
       1) cv2.VideoCapture(주소, CAP_FFMPEG)로 열기 (열기·읽기 타임아웃 20초)
       2) 프레임 1장 read → 비어 있지 않은지 확인
       3) 즉시 release (연결을 유지하지 않음)
       4) jpg 저장: CCTVID_YYYYMMDD_HHMM.jpg (예정 시각 기준, 덮어쓰기 금지)
       실패 시 10초 후 재시도, 최대 2회 (한 회차 최대 3번 접속)
  → CSV 1줄 + 텍스트 로그 기록
  → 같은 카메라 3회차 연속 실패 시 경고 1회, 이후 성공하면 "복구됨" 1회
  → 다음 회차 대기 (처리 지연·절전으로 지나간 회차는 몰아서 찍지 않고 skipped 기록)
```

## 부딪힌 문제와 해결

### 사전 확인 단계 (UTIC 접근)

| 문제 | 해결 |
|---|---|
| UTIC 공식 문서에 CCTV **목록 조회 주소·파라미터가 없음** | 인증키 승인 메일에 있던 목록 URL을 사용. JSON이 아닌 8.4MB HTML이라 1회만 받아 저장본 재사용 |
| 영상 주소에 필요한 접속값(`ID` 등)이 **공식 좌표 파일에 없음** | 사이트 내부 API를 코드로 호출하자 **"비정상적인 접근입니다"로 차단됨** → 헤더를 흉내 내 우회하지 않기로 결정 → 브라우저 개발자 도구로 값(`ID=L204`)과 m3u8 주소를 직접 확인해 설정에 수동 입력 |
| **UTIC IP 차단 기준** (동일 URL 1초 5회 이상, 10초 3회 이상 50x, 크롤링) | 재시도 최대 2회·간격 10초 이상, 회차마다 새로 접속해 1프레임만 읽고 해제, 카메라 순차 처리, 목록·내부 API는 수집 중 호출하지 않음 |
| 인증키가 **신청 IP 대역(C Class)과 묶여 있음** | 신청 PC와 같은 PC에서 진행. 최종 m3u8 주소에는 키가 필요 없어 수집 단계에는 영향 없음 |

### 수집 스크립트 단계

| 문제 | 해결 |
|---|---|
| 설정 파일이 **BOM 포함 UTF-8**이면 `tomllib`이 읽지 못함 | `utf-8-sig`로 읽도록 수정 |
| PC 시간대 설정에 의존하면 시각이 틀어짐. `zoneinfo`는 Windows에서 추가 패키지 필요 | 고정 오프셋 `UTC+09:00`으로 KST 처리 |
| `cv2.imwrite`가 Windows 한글 경로에서 실패 | `cv2.imencode` 후 직접 쓰기. `'x'` 모드로 열어 기존 파일을 덮어쓰지 않음 |
| 엑셀로 CSV를 열어두면 파일이 잠겨 기록 실패 | 쓰기 실패해도 수집은 계속, 누락 행을 텍스트 로그에 남김 |
| 테스트 캡처가 정규 데이터와 섞임 | `--once`는 파일명에 `_test`, CSV `result=test`로 분리 |
| 처리 지연·절전 시 밀린 회차 | 몰아서 찍지 않고 `skipped` 기록(예정 시각 60초 초과). 가상 시계로 연속 실패·지연·3시간 절전 복귀 시나리오 검증 |
| OpenCV로는 HTTP 상태 코드를 알 수 없음 | 50x를 구분하지 못하는 대신, 접속 횟수·간격을 제한해 차단 기준에 닿지 않도록 설계 |

## 남은 문제

- **16:50~18:00 연속 실패의 원인** — 미확인. 곧바로 실패한 점과 ID 변경 없이 복구된 점으로 보아 제공 측 일시 중단·점검 가능성이 있으나, 50x였는지는 OpenCV로 구분할 수 없었다
- **며칠 이상 장기 가동** — 약 18시간까지만 확인했다
- **실제 절전·재부팅 상황** — `skipped` 처리는 가상 시계 테스트로만 검증했다. 이번 수집에서는 `skipped` 0건
- **카메라 여러 대 운영** — 가상 테스트(2대)로만 확인했고 실제로는 1대만 수집했다
- **스트림 ID 변경 시 대응 절차** — 경고 문구는 동작했지만 실제로 ID가 바뀐 적이 없어 수행하지 않았다
