# 2026-10-27 · 에어코리아 반영과 경고 수정

> 8주차 · 배포 직후 새벽. 백엔드 조원의 에어코리아 수집 PR(#6)을 머지하고 키를 넣어 서버에 바로 반영했다. 시연에서 고장처럼 보일 지도 경고(#7)를 고쳤다.
> 전날 기록([10/26](2026-10-26_프론트개선과배포.md))의 배포에 바로 이어진 작업이다. 서비스 세션에서 한 일이다.

## 요약

- 승진 님이 시험기간 중 에어코리아 매시 수집과 CORS를 PR #6으로 올렸다. 브랜치가 #5 전에 갈라져 충돌이 있었는데, `server/NEXT.md` 맨 위에 합치는 법을 적어 두었고 승진 님이 그대로 합쳐 왔다. 테스트 103개 통과를 확인하고 머지(`cd9d7be`)
- 에어코리아 키를 서버에 넣는 데 세 번 걸렸다. 마지막에 PuTTY에서 입력이 안 보이게 넣어 **VM에서 200 응답**을 확인했다
- 서버 반영은 "시연 뒤"로 미루려다 사용자가 이유를 물어 바로 했다. 직접 한 번 돌려 **측정소 52곳의 01:00 값이 저장**됐고, 매시 50분에 자동으로 쌓인다
- 측정소 53곳이 왜 53곳인지 확인했다. 규칙은 10/19 조원 자료 스크립트에서 정해졌고 이유는 기록에 없었다. 사용자가 그대로 쓰기로 했다(패널 20곳, 밤 보간 53곳)
- 휴대폰에서 클릭 확대 중 지도 조각 하나가 실패하면 경고가 계속 남던 것을 PR #7(`23c47ee`)로 고쳐 서버에 반영했다

## 배경

10/26 밤에 수집 VM 배포를 마쳤고, 목표는 목요일(10/29) 교수님 시연이다. 같은 시각 승진 님이 "server·db도 마무리해서 올리겠다"고 했다.
그 사이 팀장 쪽에서 `server/`를 고쳤으므로(#5) 겹치지 않게 알리는 것부터 했다.

## 한 일

### 승진 님에게 알리고 PR #6 받기

- 승진 님 브랜치 `server/airkorea-ingest`는 #4 시점에서 갈라져, `main`과 합치면 `server/app.py`·`server/README.md`가 충돌했다. 둘 다 살리면 되는 충돌이었다
- `server/NEXT.md` 맨 위에 "팀장이 바꾼 것" 표와 합치는 명령·충돌 푸는 법을 넣고, 카톡 문구는 사용자가 첫 문장을 고쳐 보냈다
- PR #6 내용: 매시 50분 인천·경기 수집 → `observations`(`24:00`·결측·목록 밖 측정소·덮어쓰기), 시도별 실패 분리, 오류 메시지에 키 안 찍힘, advisory lock, CORS(localhost만, GET만)
- 승진 님이 물은 운영 방식(API 안 vs systemd timer)은 **API 안**으로 답했다. 서버의 uvicorn이 1개라 겹칠 일이 없고 lock도 있다. 매시 50분에 재시작이 겹치면 한 번 건너뛰는 정도다
- 클릭 패널의 측정소 값과 밤 처리는 둘 다 승진 님 몫이고, 화면은 이미 받을 준비가 돼 있다는 것을 사용자에게 설명했다

### 에어코리아 키 넣기 — 세 번

키가 Claude 쪽 기록에 남지 않게 사용자가 직접 넣었다.

| 시도 | 결과 | 원인 |
|---|---|---|
| PuTTY에서 `read -rs`로 입력 | 서버 119자, 에어코리아 "등록되지 않은 서비스키" | 사용자 로컬 시험에서 키는 102자·정상. 차이 17자가 `AIRKOREA_API_KEY=` 길이와 같아 **줄 전체를 붙여 넣은 것으로 추정**(확인한 것은 길이뿐) |
| 로컬 PowerShell에서 서버로 파이프 | 첫 번째는 인자 오류, 두 번째는 서버에 1글자 | PowerShell 5.1이 외부 프로그램에 따옴표·표준입력을 넘길 때 깨짐 |
| PuTTY에서 서버 스크립트로 키 값만 | **102자, VM에서 200** | — |

- 중간에 해외 IP 차단을 의심했지만, 가짜 키로 이 PC(한국)와 VM(미국)이 같은 응답을 받아 아니라는 것을 확인했다
- 키를 받으려고 만든 서버 스크립트는 끝나고 지웠다

### 서버 반영 시점

처음에는 "시연 직전에 서버를 덜 건드리자"며 반영을 시연 뒤로 미뤘다. 사용자가 "굳이 그럴 필요 있나"를 물었고, 다시 따져 보니 위험이 작았다.
바뀌는 건 API 안의 매시 요청과 CORS뿐이고, 새벽이라 쓰는 사람이 없고, 이전 커밋으로 1분 안에 되돌릴 수 있다. 오늘부터 실측이 쌓이면 다음 작업(패널 측정소 값)에도 쓸 수 있다. 그래서 바로 반영했다(`b944d1c` → `cd9d7be`).

PR #6 리뷰 댓글에는 "시연 뒤에 반영하겠다"고 적어 둔 상태라, 사용자가 사실과 다르다고 짚어 실제 반영 결과로 고쳤다.

### 측정소 53곳

사용자가 "53곳이나 썼나"를 물었다. `shared/stations.json`은 인천 내륙 사방 약 10km 안의 도시대기 측정소 전부다(내륙 20 + 내륙 밖 인천 4 + 경기 29, 서울은 범위에 없음).
클릭 패널 비교는 내륙 20곳(`use_for_compare`)만 쓰고, 밤 보간에는 53곳 모두를 쓴다. 바깥 측정소가 있으면 경계 쪽 칸이 안쪽 값으로만 쏠리지 않는다.

사용자가 "보간 때문에 내가 결정했나"를 물어 기록을 찾았는데, **규칙은 10/19 커밋 `ac06b4d`(조원 자료 스크립트)에서 들어갔고 이유는 남아 있지 않았다.** Claude가 처음에 "보간 때문"이라고 한 것은 코드와 스키마 주석을 보고 한 해석이었다고 바로잡았다.
사용자는 그대로 쓰기로 했고, 경계 쪽 효과는 실측이 아닌 기대 효과로 서비스 구상에 적었다.

### 지도 경고 수정 (PR #7)

- 증상: 클릭 확대 중 지도 조각(벡터 타일) 하나가 실패하면 "지도 일부를 불러오지 못했습니다"가 뜨고, 지도가 다 그려진 뒤에도 새로고침 전까지 남는다. 10/26 휴대폰 캡처에서 실제로 떴다
- 사용자가 "다른 브랜치가 있는지 먼저 확인하자"고 해서 확인했다. GitHub에 `main`만 있고 열린 PR이 없어서 최신 `main`에서 `web/map-warning`을 땄다
- 첫 방식("이동이 끝난 뒤 실패가 없으면 지움")은 시험에서 **도착 화면까지 실패해도 경고를 지웠다.** 도착 화면 조각의 실패도 이동이 끝나기 전에 일어나기 때문이다
- 바꾼 방식: 다 그려진 순간(`idle`) 지금 보이는 조각 중 실패한 게 없으면 지움. MapLibre 내부 값(`sourceCaches._tiles`)을 쓰므로 버전을 올리면 다시 확인하라고 주석에 적었다

## 정정된 판단

- **지도 조각이 "곧 다시 받아져 지도는 멀쩡하다"고 설명했는데 틀렸다.** MapLibre는 실패한 조각을 저절로 다시 받지 않는다. 그 화면을 벗어났다 다시 와야 새로 받는다. 10/26 캡처가 멀쩡했던 건 실패한 조각이 날아가는 도중의 화면 것이었기 때문으로 보인다
- **측정소 53곳을 "보간 때문에 넣었다"고 처음에 말했는데,** 기록에는 그런 판단이 없었다(위)
- **`server/NEXT.md` 보강 커밋이 본문 없이 먼저 올라갔다**(`8801af6`). 편집이 실패했는데 확인하지 않고 커밋했다. 바로 다음 커밋(`b944d1c`)에서 본문을 넣었다
