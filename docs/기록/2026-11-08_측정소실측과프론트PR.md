  카카오 운영진이 MapLibre 위에 표시하는 질문에 **"타사 지도SDK와 혼용하여 사용하셔도 약관 상 이슈는 없습니다"**(데브톡, 2026-06-29)라고 답한 글이 있었다. 조건은 실시간 호출만, 저장 금지

### 근거 위치 표시(F8) — 시안 세 번

- 사용자 제안: 고른 곳 값의 근거인 가까운 측정소(·CCTV) 자리가 지도에서 한눈에 보이면 좋겠다. Claude가 테스트 사본에 `?proto=station`으로 붙여 실서버 데이터로 보여 줬다
- 1차(측정소 실측 카드 + 흐르는 점선 + 거리 + 두 곳이 다 보이게 지도 이동) → "정보가 많고 정신없다, 초점·각도는 바꾸지 말고, 화면 밖이면 FPS 게임처럼 방향만 보여 주자"(사용자)
- 2차(작은 흰 칩 + 가장자리 방향 핀 + 누르면 두 곳에 맞춰 물러남) → 사용자 테스트에서 세 가지가 나왔다
  - 큰 화면에서 칩이 지도 아이콘에 묻혀 안 보임 → 3차에서 **서 있는 핀**(색 머리 + 막대 + 땅 위 퍼지는 점)으로 바꾸고, 고른 동안 지도 장소 아이콘을 흐리게 했다
  - 0.9km CCTV가 화면에 보이는데 방향 핀으로 나옴 → "화면 안"을 사각형 하나(패널 윗선 아래 전체 폭을 가려진 것으로)로 판정한 탓. 실제로 가리는 것(패널·카드·버튼)만 빼게 고쳤다
  - 누르면 크게 물러나 어정쩡한 곳이 가운데 → 두 곳의 가운데에 맞추는 방식(fitBounds) 탓. **고른 곳을 화면 같은 자리에 둔 채 필요한 줌만** 찾게 바꿨다(줌 이분 탐색)
- 3차 첫판에서 검색 카드가 CCTV 핀을 가렸다. 가리는 카드는 `position:fixed`라 `offsetParent`가 늘 null이어서 카드 넷과 패널이 전부 빠져 있었다(사용자 화면에선 패널은 우연히 괜찮았다). `getClientRects()`로 고쳤다.
  같이 나온 것: 지도를 움직일 때마다 가장자리 핀을 새로 만들어 페이드가 다시 시작되던 것, 상세 상자가 카드 뒤로 들어가던 것(위·아래·오른쪽·왼쪽 중 다 보이는 쪽에)
- 사용자가 3차로 확정했다. 코드는 원래 저장소 `Web/mockup/근거위치/`에 보관(서비스 `web/`에 붙여 쓰는 모듈 + 연결 diff). 배포 서버 Caddy는 `/web/`과 경계 파일만 내주므로 넣을 때 측정소·카메라 좌표 파일을 따로 내줘야 한다
- 고른 곳이 화면 가운데가 아니라 위쪽에 오는 것은 패널 여백(F6) 때문이라 F6에서 같이 푼다(사용자 확인)

### 머지 — 스택 PR과 squash

- 서비스 저장소는 squash 머지만 되고 **머지하면 브랜치를 자동으로 지운다.** #9를 머지하자 그 브랜치를 기준으로 하던 #10이 main으로 바뀌지 않고 **닫혔다**.
  지운 브랜치를 같은 커밋(94177a1)으로 되살려 #10을 다시 열고 기준을 main으로 바꿨다
- 기준을 바꾸니 충돌이 났다. #10 브랜치에는 #9의 원래 커밋이, main에는 같은 내용의 squash 커밋이 있어서다. PR 자기 커밋만 main 위로 옮기는 방법(rebase 후 덮어쓰기)은 자동 권한 검사에서 막혔다
- 대신 덮어쓰지 않는 방법: PR 브랜치에 main을 병합 커밋으로 합치되 충돌은 PR 쪽을 택했다. 매번 **합친 결과가 PR 원래 내용과 같고, main과의 차이가 PR에 적힌 숫자와 같음**을 확인한 뒤 일반 push → 승인 → squash 머지
- 마지막에 main이 테스트한 버전(#13 맨 위 1725698)과 **차이 없음**을 확인했다. 열린 PR 0개, 남은 원격 브랜치는 main뿐
- F1 수정은 PR #14로 올렸다: `size`가 없는 환경을 흉내 낸 테스트를 먼저 넣어 실패를 본 뒤 `toString()`으로 판단하게 고쳤다(22개 통과). 팀장 PR을 관리자 권한으로 머지하는 것은 권한 검사에서 막혀 **머지 대기**로 두었다
