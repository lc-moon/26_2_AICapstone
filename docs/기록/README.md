## 흐름 요약

**2주차 — 되는지 확인**
CCTV 영상을 코드로 가져올 수 있는가, 며칠간 무인으로 돌아가는가를 봤다.
용현사거리 한 대, 10분 간격, 집 PC에서 실행.
테스트가 목적이었으므로 확인이 끝난 뒤 수집을 멈추고 다음 단계로 넘어갔다.

**3주차 — 옮길 곳 만들고, 제대로 다시 만들기**
먼저 클라우드 서버를 구축하고 비용을 따졌다. 클라우드 IP에서도 스트림 접속이 되는지 검증했다.
같은 시기에 숭의 측정소 분석으로 **고농도 데이터가 거의 없다**는 구조적 리스크가 드러났다.

이어서 카메라 소스를 정하는 과정에서 fitic 목록 API를 발견해 수작업 전제가 사라졌고,
237대를 자동 스크리닝해 20대를 골랐다. 수집기를 새로 써서 배포하고 가동했다.

수집이 돌기 시작한 뒤에는 문서를 정리했다. 갱신되는 문서와 그날의 기록을 갈라
같은 사실이 두 군데에서 어긋나지 않게 하고, 기록 남기는 일 자체를 스킬로 만들었다.

첫 하루치가 쌓이자 추정으로 적어둔 값들을 실측으로 바꿨고, 그 숫자가 판단을 몇 개 뒤집었다.
디스크 압박 시점이 모델 마감과 겹치지 않는다는 것이 드러나 GCS 동기화가 우선순위에서 내려갔다.
같은 맥락에서 **기상값을 직전 시간으로 대체하던 경로를 없앴다** — 결측을 메우는 대신
결측으로 남기고 바로 알리는 쪽으로, 라벨의 신뢰성을 택했다.
