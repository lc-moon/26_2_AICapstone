## 3. 화면 (프론트)

**지도**: MapLibre GL JS + OpenFreeMap Liberty 스타일. 사용자가 보여 준 참고 이미지와 같은 스타일이고 무료·키 없음.
3D 건물은 확대 수준 14부터 나온다. 그래서 인천 전체 화면(약 10)은 평면이고, 클릭해서 확대해야 건물이 선다.

**첫 화면**
- 인천 내륙이 꽉 차게, **살짝 기울여서**(40°) 시작. 지도와 농도 색만 보인다
- 도로 번호 표지(`13;25` 같은 숫자)는 뺀다. 인천 밖 지명·도로명은 아예 숨긴다(경계에 걸려 잘려 보이지 않게)
- **격자는 보이지 않는다.** 계산에만 쓰고, 화면에는 격자값을 이어 칠한 뒤 흐리게 해 구름처럼 보이게 한다
- 같은 등급 안에서도 농도에 따라 명암을 다르게
- 색은 에어코리아식 4단계(좋음 파랑·보통 초록·나쁨 주황·매우나쁨 빨강)를 **파스텔톤**으로
- **인천 밖은 라벨까지 옅게 가리고** 경계선을 그어 "인천 시범 서비스"로 보이게
- 화면에 두는 것은 기준 시각(몇 시 몇 분), 범례, 출처뿐. CCTV·측정소 위치와 숫자는 표시하지 않는다

**클릭하면**
- 그곳으로 확대(3D 건물이 보이는 수준)하고, 확대할수록 색을 옅게 해 건물이 묻히지 않게
- 패널: 추정 농도, 등급, **가까운 측정소 실측값**, 각 값의 기준 시각을 나란히
  (예: 13:20 CCTV 추정 / 송도 측정소 12~13시 평균)
- 범위 밖·바다를 누르면 "인천 내륙만 볼 수 있어요"

**프론트 첫 버전 이후 정한 것** (10/26, 금혁 님 PR #3 머지 뒤 팀장 개선 PR #4)
- 첫 화면: 컴퓨터는 40° 기울인 채 인천 전체가 꽉 차는 줌(화면 비율에 맞춰 계산), 휴대폰은 iPhone 16(393px) 기준으로 조금 잘리게 더 확대
- 휴대폰은 제목 카드를 기준 시각만, 범례는 제목 아래 한 줄(PM2.5·수치 유지, 설명 문구 뺌). 출처 표기가 범례에 가려지면 안 된다(표기 의무)
- 클릭한 곳은 컴퓨터는 화면 가운데, 휴대폰은 하단 패널 위 영역 가운데. 닫으면 그 지점을 화면 가운데로
- OS '동작 줄이기' 설정과 상관없이 애니메이션을 보인다(MapLibre가 이 설정이면 건너뛰므로 `essential: true`)
- 도구 버튼은 아이콘 막대(전체 보기·2D/3D·내 위치·새로고침). 새로고침은 동작하니 남겨 둔다
- 도로명·지하철역은 줌 11, 나머지 장소는 줌 12부터. 지도 글자의 영문·한글 병기는 그대로(외국인도 볼 수 있게)
- 기준 시각 옆 'n분 전'. 내 위치는 오차가 500m(격자 반 칸)를 넘으면 "PC에서는 위치가 부정확할 수 있어요"
- 사파리(아이폰)는 canvas `filter`를 기본 지원하지 않아 구름 흐림을 다른 방식으로. **배포 후 실제 아이폰 확인 필요**
- 바다 쪽 경계는 둥글리고 만 입구는 직선으로 메운 화면용 경계(`display`)로. 누를 수 있는 땅은 모두 값이 나와야 한다(§2 격자·경계)

## 4. DB 스키마 (PostgreSQL)

```sql
-- 고정 정보
CREATE TABLE grid_cells (
  grid_id    integer PRIMARY KEY,   -- frames.values 배열의 순서(0부터)
  row integer, col integer,
  center_lon double precision, center_lat double precision,
  geom       jsonb NOT NULL,        -- GeoJSON. 화면엔 안 그리고 계산·클릭 판정용
  gu         text                   -- 클릭 패널의 "연수구 송도동 부근"
);
CREATE TABLE cameras (
  camera_id text PRIMARY KEY,       -- fitic 관리번호. 이름으로 잇지 않는다
  name text NOT NULL, lat double precision, lon double precision,
  grid_id integer REFERENCES grid_cells, active boolean DEFAULT true
);
CREATE TABLE stations (
  station_name text PRIMARY KEY, sido text,
  network text,                     -- 도시대기/도로변대기/항만 …
  lat double precision, lon double precision,
  use_for_compare boolean           -- 클릭 패널 비교·밤 보간에 쓸지
);
CREATE TABLE model_versions (       -- 어느 모델이 낸 값인지
  model text PRIMARY KEY, deployed_at timestamptz,
  cv_mae real, test_mae real, note text
);

-- 시계열
CREATE TABLE estimates (
  camera_id text REFERENCES cameras,
  slot timestamptz,                 -- :00/:20/:40 회차
  captured_at timestamptz,          -- 실제 촬영 시각(13:20:07)
  pm25_est real,                    -- 추정 안 했으면 NULL (메우지 않는다)
  status text NOT NULL,             -- 정상 / 비 / 습도 / 결측 …
  humidity real, rain_60m real,
  model text REFERENCES model_versions,
  estimated_at timestamptz, received_at timestamptz DEFAULT now(),
  PRIMARY KEY (camera_id, slot)
);
CREATE TABLE observations (
  station_name text REFERENCES stations,
  data_time timestamptz,            -- 구간 끝. 13:00 = 12~13시 평균
  pm25 real, pm10 real, pm25_flag text,
  fetched_at timestamptz, updated_at timestamptz,  -- 값이 나중에 고쳐지면 덮어쓰기
  PRIMARY KEY (station_name, data_time)
);
CREATE TABLE frames (               -- 애니메이션·지도용. 위 두 표로 언제든 다시 계산 가능
  slot timestamptz PRIMARY KEY,     -- 낮은 20분, 밤은 정시
  source text CHECK (source IN ('cctv','station')),
  basis_time timestamptz,           -- 밤이면 어느 시간 실측인지
  n_inputs smallint, inputs text[], -- 쓴 카메라·측정소
  values real[] NOT NULL,           -- grid_cells 순서
  method text, model text, created_at timestamptz DEFAULT now()
);
CREATE TABLE daily_metrics (        -- 하루 단위 추정 대 실측 (실측 대조 자동화)
  day date, camera_id text, station_name text, model text,
  n integer, mae real, bias real,
  PRIMARY KEY (day, camera_id)
);
CREATE TABLE ingest_log (           -- 로그
  id bigserial PRIMARY KEY,
  source text,                      -- estimator / airkorea
  started_at timestamptz, rows_in integer, rows_upserted integer, error text
);
```

`frames.values`를 배열로 두는 이유: 격자 모양은 한 번만 보내고, 애니메이션은 시각별 숫자 배열만 받으면 된다.
프레임 사이는 프론트가 선형으로 섞어 부드럽게 넘긴다.

## 7. 역할 분배 가이드에 넣을 기술 메모

역할 분배 가이드를 만들 때 이 절을 옮긴다. 조원이 알아야 할 내용이다.

- **브라우저가 API를 부른다.** 화면 파일(HTML·JS)을 받은 뒤, 그 JS가 사용자 브라우저 안에서 백엔드 API에 농도를 묻는다.
  페이지가 `https://`로 열렸는데 API 주소가 `http://`면 브라우저가 막는다(혼합 콘텐츠 차단). 그래서 API도 HTTPS여야 한다
- **HTTPS 인증서는 도메인에 붙는다.** IP 주소만으로는 어렵다. 도메인 하나 + Caddy(인증서 자동 발급·갱신)
- **화면과 API를 한 VM, 한 주소에 두면** CORS 설정이 필요 없다. 프론트를 로컬에서 개발할 때만 `localhost`를 허용해 두면 된다
- **인증키는 백엔드에만.** 화면 코드에 넣은 값은 누구나 볼 수 있다. OpenFreeMap은 키가 없다
- **사양**: e2-micro(1GB)에 Caddy + API + PostgreSQL이 들어간다. 메모리가 빠듯할 때를 대비해 스왑 1~2GB를 잡아 둔다
- 추정기 → 백엔드 전송은 서버끼리라 브라우저 규칙과 무관하지만, 인증 토큰이 오가므로 HTTPS로 보낸다
