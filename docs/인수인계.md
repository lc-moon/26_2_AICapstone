## 3. 검증된 사실 (재확인 불필요)

1. **클라우드 IP에서 CCTV 스트림 접속 가능**
   - 대만(Cloud Shell)·오리건(VM) 두 곳에서 성공, 해상도도 집 PC와 동일
   - → 해외 IP·데이터센터 IP 차단 없음, Referer 검사 없음

2. **fitic 카메라 목록을 API로 받을 수 있다** (2026-09-21 확인)
   ```
   POST https://www.fitic.go.kr/gis/selectListData.do
   body: type=cctv&keyword=
   ```
   - 응답은 **이중 인코딩**(문자열 안에 JSON)이라 두 번 파싱해야 함
   - 필드: `CCTV_MNGM_NMBR`(번호) `CCTV_NM`(이름) `X_CRDN`(경도) `Y_CRDN`(위도) `HTTPADDR`(스트림)
   - **인천 전역 237대**. `HTTPADDR`의 `http://61.40.94.13:1935` → `https://cctv.fitic.go.kr`로 치환해 사용
   - → **스트림 주소를 개발자도구로 캘 필요가 없어짐.** UTIC도 불필요해짐(출처 표기용으로만 남음)
   - 공식 오픈 API가 아니라 지도 페이지 내부 엔드포인트이므로 **목록 조회는 하루 1회 수준으로만**

3. **실제 스트림 해상도** — 960×540이 150대, 1280×720이 60대, 640×360 이하 18대
   - 브라우저 플레이어로 보면 커 보이지만 **업스케일**임. 원본은 위 값

4. **PM2.5는 3개월 소급 조회 가능**
   - `getMsrstnAcctoRltmMesureDnsty` + `dataTerm=3MONTH`로 2,207시간 수신 실적
   - **약관 제5조상 3개월이 상한**이며 그 이상은 국립환경과학원 대기환경월보의 확정 데이터를 써야 함
   - → 월 1회 백필은 권장이 아니라 **필수 운영 규칙**

5. **에어코리아 데이터 생성주기 = 매시 15분 내외** (기술문서 0.2절)
   - `dataTime=13:00` 자료는 13:15쯤 게시됨 → 라벨 병합은 수집과 분리된 후처리로 둘 것

6. **기상청 초단기실황은 백필 불가 — 최근 1일치뿐** (2026-09-21 실측)
   - 1일 전부터 `"최근 1일 간의 자료만 제공합니다"` 응답
   - → **이미지와 함께 상시 수집해야 함.** 지나가면 영구 손실
   - 자료는 매시 정시 기준, 게시는 매시 **40분쯤** (14:37에 1400 자료 확인됨)
   - 격자 변환(Lambert)은 서울 종로(60,127)·인천 미추홀(54,124)·제주(53,38)로 검증 완료

7. **에어코리아 측정소 목록은 위경도를 준다** — TM 변환 불필요
   - `getMsrstnList`의 `dmX`=위도, `dmY`=경도. (TM은 `getNearbyMsrstnList` 쪽 얘기)
   - `mangName`으로 도시대기 / 도로변대기 / 항만 / 교외 구분됨

8. **이미지는 소급 불가** — 과거 스트림이 없음. 수집 가동률이 곧 데이터셋 크기

9. **Ubuntu 22.04는 사용 불가** — Python 3.10이라 `tomllib`(3.11+)이 없음. 24.04 사용

## 6. 확정된 수집 사양

| 항목 | 값 | 근거 |
|---|---|---|
| 소스 | fitic(인천교통정보센터) **20대** | §7 |
| 주기 | **20분** (매시 00·20·40) | 아래 설명 |
| 야간 | **태양고도 0° 미만 건너뜀** | 조명 조건이 달라 학습 불가 |
| URL | `cameras.toml`엔 번호만, 실행 시 목록 API로 조회 + `url_cache.json` 캐시 | §3-2 |
| 저장 | `data/images/{번호}/{YYYY-MM-DD}/{HHMM}.jpg` | |
| 품질 | JPEG 95 | 원경의 미세 대비가 곧 신호라 압축에 민감 |
| 알림 | Discord 웹훅 — 연속 3회 실패 / 복구 / 회차 전멸 / 비정상 종료 / **일일 요약** | |
| 용량 | 4개월 약 **18GB** (프레임 평균 243KB) | 30GB 디스크에 GCS 동기화 병행 필요 |
| 기상 | 격자 **13개**, 매시 **:40**에 그 시각 정시 자료 | 백필 불가라 야간에도 수집 |
| PM2.5 | **상시 수집 안 함.** 배치로 백필 | 3개월 소급 가능 |

**주기를 20분으로 정한 이유.** 지도교수 지적대로 PM2.5 라벨이 1시간 단위라 시간당 6장(10분)은 독립 샘플이 아님. 다만 1시간 1장은 **한 번 실패하면 그 시간이 영구 손실**이고, 차량 가림·시각 정렬 문제에도 대응 못 함. 그래서:

> **수집 주기 ≠ 학습 샘플링 주기**
> 수집은 시간당 3장(결측·가림 보험), 학습은 시간당 1샘플로 집계하거나 대표 1장 선택.
> **train/test는 무작위가 아니라 날짜·시간 기준으로 분할할 것** — 근접 프레임이 양쪽에 걸리면 성능이 부풀려짐.

### 프로세스 구성 — 상시 1개 + 배치 1개

백필 가능 여부로 갈린다. **지나가면 사라지는 것만 상시로 받는다.**

```
[상시] collect_cctv.py   이미지(20분) + 기상(매시 :40)     ← 둘 다 백필 불가
[배치] build_labels.py   PM2.5 백필 + 병합 → labels.csv    ← 3개월 안에 언제든
```

문서 초안에는 PM2.5도 1시간 주기 상시 프로세스로 적혀 있었으나, 3개월 백필이 되므로 불필요하다.
기상을 별도 프로세스로 분리하지 않은 이유는, **기상값은 이미지가 있어야만 의미가 있어서** 이미지 수집기가
죽은 시간대의 기상값은 어차피 쓸 데가 없기 때문이다. 분리해도 실질적으로 지켜지는 게 없고,
§1의 최대 리스크가 "조용히 멈추는 것"인 만큼 **감시 지점을 1개로 유지하는 편이 낫다.**
기상 API 실패는 `try/except`로 격리해 이미지 캡처를 막지 않는다.

## 7. 카메라 선정 기록 (2026-09-21 확정)

`Tools/screen_fitic.py`로 237대를 자동 채점 후 육안 검수. **최종 20대**는 `Collector/cameras.toml` 참조.

**자동 판정 기준** (프레임 1장에서 계산)

| 지표 | 통과선 | 의미 |
|---|---|---|

| 하늘 가로 균일도 | p85−p15 ≤ 15 | 얼룩지면 기준이 안 됨 |
| 하늘 포화 | 240 이상 픽셀 비율 | 날아가면 정보 없음 |
| 원경 최저 대비 | 낮을수록 좋음(음수는 실격) | 소실 구간 존재 여부 |
| 해상도 | 960폭 미만 감점 | 원경 디테일 |

**걸러낸 실패 유형**

- **하늘 없음 161대** — 구도심 교차로 대부분. 앞이 건물에 막혀 지평선이 안 보임
- **노면 오인 12대** — 균일한 아스팔트를 하늘로 착각. "하늘은 지면보다 밝다" 조건으로 제거
- **하늘 부족 17대 / 불균일 15대**
- **PTZ 2대** — 부평사거리(50), 영종도삼목지하차도(234). 프레임 2장의 **상단만** 비교해 검출(차량 통행 영향 제거)

**성공 화각의 공통점**: 카메라가 높고 · 앞이 트여 있고(매립지·수면·넓은 도로축) · 3km 이상 떨어진 고층 건물군이 보임.
반대로 구도심 교차로·관광지 도로는 대부분 실패.

**측정소 매칭** (2026-09-21)

카메라 20대에 최근접 **도시대기** 측정소를 붙이면 **13곳**, 하루 312건(한도 500).
대부분 1~3km 이내이며 최장이 초지교사거리-길상 4.0km다.

도로변대기를 쓰지 않는 이유: 도로 바로 옆이라 차량 배기 영향으로 농도가 국지적으로 튄다.
우리 이미지는 **수 km 시선 경로의 공기를 적분한 값**이라 성격이 정반대다. 거리가 조금 멀어도 지역 대표 농도인 도시대기가 맞다.

**을왕해수욕장(11)은 이 단계에서 제외했다.** 최근접 측정소가 운서 **11.4km**로 나머지(1~3km)와 차이가 크고,
영종·용유도에 대안 측정소가 없다. 화각도 중위권이라 라벨을 못 믿는 카메라를 넣으면
모델 오차의 원인이 화각인지 라벨인지 구분되지 않는다.

**한계로 남겨둘 것**: 이미지는 카메라 지점이 아니라 **시선 경로 전체의 공기**를 보는데, 라벨은 측정소 한 점의 값이다.
인천은 측정소가 촘촘해 차이가 크지 않을 것으로 보지만, 특정 카메라만 오차가 클 때 원인 후보로 둘 것.

**주의**: 원경 타겟은 **건물이 안전**하다. 산림은 9~11월 단풍·낙엽으로 반사율이 바뀌어 수집 기간과 정면으로 겹침.

```

python Tools/screen_fitic.py --rescore    저장된 프레임 재채점 (약 5초)
```

### 배포·운영

배포 중 겪은 것 (같은 실수를 반복하지 않도록)
- `cameras.toml`에 Windows 절대경로가 박혀 있어 리눅스에서 실패 → 상대경로로 변경
- 셸 스크립트가 CRLF로 체크아웃되면 실행 불가 → `.gitattributes`로 LF 고정
- VM이 미국 리전이라 캡처가 느리다. 로컬 1~2초 → **GCP 5~7초**. 20대에 약 2분이라 20분 슬롯엔 여유 있음
- `.env`는 git에 없으므로 서버에 따로 전달해야 한다. 붙여넣은 뒤 **값 길이를 대조할 것**
